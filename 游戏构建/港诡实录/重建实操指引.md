## 第 3 节 · 从零重建（App 整个没了才需要）

### 3.1 准备

- 空闲空间：**≥ 25 GB**（dmg 6.9 GB + 解出来的 app 16 GB）
- 目录必须是**纯英文路径**。本机用 `/Volumes/SSD/Game/ParanormalHK/`，
  而且把 app 从 `港诡实录.app` **改名成 `Paranormal HK.app`** —— 中文名在 Wine 里会被转成 `????`
  （霍格沃茨那份文档的 1 号坑，这里同一个道理）
- 时间：约 10 分钟（挂载 + 拷贝）

### 3.2 装出原始 app

```sh
cd /Volumes/SSD/Game/ParanormalHK
hdiutil attach "/Volumes/SSD/Game/港诡实录+Paranormal+HK+v1.04+[www.getmacapp.com].dmg"
ditto "/Volumes/<挂载卷>/港诡实录.app" "./Paranormal HK.app"
hdiutil detach "/Volumes/<挂载卷>"

# 必做：去掉隔离属性，否则双击报「已损坏，无法打开」
xattr -dr com.apple.quarantine "./Paranormal HK.app"
```

> dmg 里还有个 `Sentinel.app` 和 `双击打开我.webloc`，那是打包站的分发壳，**不需要，别装**。

### 3.3 修 bundle 里三个必坏的配置

```sh
APP="/Volumes/SSD/Game/ParanormalHK/Paranormal HK.app"
SUP="$APP/Contents/SharedSupport"

# ① libinotify 没接进 wine/lib → wineserver 起不来
#    现象：dyld[xxxx]: Library not loaded: @rpath/libinotify.0.dylib / no LC_RPATH's found
ln -sf ../../../Frameworks/libinotify.0.dylib "$SUP/wine/lib/libinotify.0.dylib"
ln -sf ../../../Frameworks/libinotify.dylib   "$SUP/wine/lib/libinotify.dylib"

# ② dosdevices 里是打包者自己机器的盘符，全是断链，只留 c: 和 z:
ls "$SUP/prefix/dosdevices/"      # 正常只应该有 c: c:: z: z:: d:: …
rm -f "$SUP/prefix/dosdevices/d:" "$SUP/prefix/dosdevices/e:" \
      "$SUP/prefix/dosdevices/f:" "$SUP/prefix/dosdevices/g:" \
      "$SUP/prefix/dosdevices/h:" "$SUP/prefix/dosdevices/i:"

# ③ 自检断链（链接断着 wine 会静默失败，很难查）
find "$APP" -type l | while read l; do [ -e "$l" ] || echo "断链: $l"; done
```

### 3.4 换掉原厂启动器（这一步决定能不能双击玩）

原厂 `Kegworks` 在 macOS 15 上一定会失败：

```
Starting Kegworks
Starting Wine application
Starting with start.exe "C:\Program Files (x86)\A018\PuzzleGame\Binaries\Win64\PuzzleGame-Win64-Shipping.exe"
ERROR: The operation couldn't be completed. (KegworksSdk.FileUtilsError error 1.)
Closing Kegworks
```

窗口闪一下就没了、日志一个字不写。修法不是配置，是**换启动器**：

```sh
bash "/Volumes/SSD/Game/游戏构建/港诡实录/_build/build_launcher.sh"
```

脚本会自动把原厂启动器备份成 `MacOS/Kegworks.orig`，再装新的。三条规矩别改（和霍格沃茨一样）：

1. **编译输出必须直接叫 `/tmp/Kegworks`**。ad-hoc 签名的 identifier 由文件名派生，名字不一致 → 判签名无效。
2. **先签名、再拷进 bundle**。在 bundle 内签会扫 16 GB。
3. **拷进去用 `ditto --norsrc` + `xattr -c`**，别用 `cp -f`。

### 3.5 首次运行

```sh
open -a "/Volumes/SSD/Game/ParanormalHK/Paranormal HK.app"
```

会依次发生：

1. 弹「**想要访问可移除宗卷上的文件**」→ 点**允许**（一次性）
2. 出现「港诡实录 Paranormal HK · 启动设置」面板
3. 点「开始游戏」→ 20~40 秒后出现游戏窗口（wine 初始化 + CEF 起来 + 第一次编译着色器）
4. 主菜单「港詭實錄 -ParanormalHK-」

**跳过面板直接开**：

```sh
touch ~/Library/Application\ Support/MacNativeGames/PARANORMAL/autoplay
open -a "/Volumes/SSD/Game/ParanormalHK/Paranormal HK.app"
```

## 第 4 节 · 启动器面板

源码 `_build/phk_launcher.m`（约 560 行，AppKit，无 nib）。它替掉原厂启动器，干四件事：
**写 ini → 清残留 → 按 D3DMetal 那套环境变量起 wine → 90 秒没出窗口就自己重来一次**。

| 面板项 | 落到哪里 |
|---|---|
| 画面档 流畅 / 均衡 / 清晰 | `GameUserSettings.ini` 的 `sg.*`（全 0 / 1 / 2）；流畅档另外在 `Engine.ini` 关掉阴影、SSR、体积雾、AO、景深、动态模糊、泛光、镜头光晕、色散 |
| 分辨率 1280×720 / 1600×900 / 1920×1080 / 1024×576 | `GameUserSettings.ini` 的 `ResolutionSizeX/Y`，同时作为 `explorer /desktop=` 的尺寸 |
| 帧率上限 60 / 30 / 不限制 | **VSync**（60 = `bUseVSync=True`；不限制 = `False`）；30 档再叠一个 `t.MaxFPS=30` |
| 内存压力 省内存 / 极省 / 标准 | `Engine.ini`：`r.Streaming.PoolSize`（256 / 128 / 1000）、`r.Streaming.UseFixedPoolSize`、`r.Streaming.MaxTempMemoryAllowed`（16 / 8）、`r.MipMapLODBias`（0 / 1 / 0）、`r.ScreenPercentage`（100 / 85 / 100） |
| 显示 Metal HUD | 环境变量 `MTL_HUD_ENABLED=1`（**唯一可靠的帧率观测手段**，见第 6 节） |
| 输出 Wine 日志 | `WINEDEBUG=err+all`（否则 `-all`） |

面板本身不做全屏切换，游戏窗口是 Wine 虚拟桌面里的一个窗口（`explorer /desktop=PHK,<尺寸>`）。

**看门狗**：启动后每 2 秒查一次屏幕上有没有属主/标题含 `PuzzleGame` 的窗口；
90 秒还没等到就清场重来一次，两次都失败就报错停下（不再无脑重试）。

## 第 5 节 · 环境变量全表（启动器会自动设，手工排查时对照）

| 变量 | 值 | 作用 / 不加会怎样 |
|---|---|---|
| `WINEPREFIX` | `<app>/Contents/SharedSupport/prefix` | 必需 |
| `WINEDLLPATH` | `<sup>/wine/lib/wine` | 找不到 wine 内置 dll |
| `WINEDLLPATH_PREPEND` | `…/d3dmetal/wine` | D3D11/DXGI 的 D3DMetal 版优先 |
| `CX_APPLEGPT_LIBD3DSHARED_PATH`<br>`CX_APPLEGPTK_LIBD3DSHARED_PATH` | `…/d3dmetal/external/libd3dshared.dylib` | D3DMetal 接线 |
| `DYLD_FALLBACK_LIBRARY_PATH` | `<app>/Contents/Frameworks` | **少了它 `libinotify` / `libfreetype` 全找不到**，wineserver 起不来 |
| `WINEESYNC` / `WINEMSYNC` | `1` | 同步原语加速 |
| `WINE_CPU_TOPOLOGY` | `4:0,1,2,3` | 不设容易在启动阶段崩（霍格沃茨踩过同款） |
| `WINEDEBUG` | `-all` | 关日志。排查时临时改 `err+all` |
| `MTL_HUD_ENABLED` | `1` | 出 Metal HUD，能看 FPS/Pre/GPU/Mem |

原厂 `Info.plist` 里还有 `D3DMETAL=1`、`MOLYBDENUMVKCX=1`、`DXVK=0`、`ADVERTISE_AVX=1` 这些开关，
现在都由启动器直接给环境变量，**不用再动 Info.plist**（改了反而破坏签名）。

## 第 6 节 · 坑位清单（按"卡住时间"排序）

1. **原厂启动器在 macOS 15 上必挂**：`KegworksSdk.FileUtilsError error 1`，窗口闪退、日志空白。
   这不是配置问题，只能换启动器（3.4 节）。霍格沃茨那份文档里同款（当时叫 `SikarugirSdk`）。
2. **`libinotify` 断链**：复制到别的目录后 `dyld: Library not loaded: @rpath/libinotify.0.dylib`。
   原厂 dmg 里 `wine/lib/` 本来就没这个文件，靠 `DYLD_FALLBACK_LIBRARY_PATH` 兜着；
   一旦环境变量没给到就直接死。**根治办法是建符号链接**（3.3 ①）。
3. **`com.apple.quarantine`**：从 dmg 拷出来的 app 双击报「已损坏，无法打开」。`xattr -dr` 清掉即可。
   注意清完 `open -a` 才能起来，否则会一直弹这个框并把启动卡在那里。
4. **游戏退出时会重写 `GameUserSettings.ini`**，而且只留一个 `[Internationalization] Language`。
   也就是说**手改画质设置活不过一局**。面板的做法是每次启动前重写 —— 别去改那个文件，改面板。
5. **不能直接 `wine <exe> -windowed` 起游戏**。实测这种起法有相当大概率静默退出（进程没了、没窗口、没日志）。
   必须用 `wine explorer /desktop=PHK,<尺寸> <exe>` 包一层，装上启动器后连续 6 次启动 6 次成功，
   出窗口耗时 15~25 秒。
6. **`t.MaxFPS` 这个游戏不认**。写进 `Engine.ini` 照样跑到 96 fps。**锁帧只能用 VSync**
   （`bUseVSync=True`，显示器 60 Hz 就锁在 60）。实测锁上之后帧时间曲线是平的（60.00 [60.00, 60.00]）。
7. **虚拟桌面同名会复用旧尺寸**。`/desktop=PHK,1024x576` 在 `PHK` 已经存在时**不生效**，
   窗口还是上一次的尺寸。所以分辨率必须同时写进 `GameUserSettings.ini`，别只靠命令行参数。
8. **`DYLD_FALLBACK_LIBRARY_PATH` 少了 `Contents/Frameworks`** → 字体库和 inotify 都找不到，
   表现为窗口塌成 0 尺寸或者 dyld 直接报错。这是霍格沃茨那份文档里折腾最久的坑，同款。
9. **`WINE_CPU_TOPOLOGY` 不能省**，否则启动阶段容易崩。
10. **prefix 里的用户名是 `Kegworks`**，不是 macOS 用户名。找配置/存档时写死它。
11. **强杀游戏会留下 wine 服务和 `winedevice.exe` 进程**，它们占着 prefix，下次启动就卡住。
    清理：`pkill -9 -f "Paranormal HK.app/Contents/SharedSupport"` + `wineserver -k`，然后**等 2~3 秒**再起。
12. **Rosetta 2 必须先装**。整个 Wine 是 x86_64 薄二进制，没 Rosetta 连 `wine --version` 都跑不起来。
13. **`Info.plist` 里的名字是打包者的**：`CFBundleName = 割麦网`、`CFBundleShortVersionString = ☇ 割麦网 | www.getmacapp.com`。
    菜单栏和程序坞会显示「割麦网」。改法：
    ```sh
    P="$APP/Contents/Info.plist"
    /usr/libexec/PlistBuddy -c "Set :CFBundleName 港诡实录" "$P"
    /usr/libexec/PlistBuddy -c "Add :CFBundleDisplayName string 港诡实录" "$P"
    /usr/libexec/PlistBuddy -c "Set :CFBundleShortVersionString 1.04" "$P"
    ```
    改完 app 的签名封印会失效，但本机（已清 quarantine、ad-hoc 签名）实测照常运行；
    真要保险就重新签名：`codesign --force --sign - "$APP/Contents/MacOS/Kegworks"`。
14. **UE4 Shipping 版没有控制台**，`stat fps` 用不了。想看帧率只能开 `MTL_HUD_ENABLED=1`，
    HUD 会显示 FPS / Pre（CPU 帧时间）/ GPU / Mem，并且**只在游戏窗口内部**，屏幕截图要对着窗口抓。
15. **内存压到 1.5 GB 就到底了**。这 1.5 GB 是 Wine + Rosetta + UE4 堆的固定成本；
    把纹理池从 1000 压到 128、渲染分辨率打 85%，总共只再省十几 MB —— 真正的内存在引擎堆里，不是纹理。
16. **`open -a` 只会"激活"已经在跑的启动器**，不会重新走一遍启动流程。
    所以写脚本自动开游戏时，`autoplay` 标记必须配一次「把启动器本体也杀掉」：
    ```sh
    pkill -9 -f "Paranormal HK.app/Contents"     # 注意是 Contents，不是 Contents/SharedSupport
    ```
    只杀 wine 进程的话，`touch autoplay && open -a` 会静默什么都不发生（本机踩过，三次全"失败"其实是没启动）。

## 第 9 节 · 性能基线与调优边界

**实测数据（MacBook Air M4 / 16 GB，macOS 15.6，2026-10-29）**：

| 配置 | 分辨率 | FPS | Pre（CPU） | GPU | Mem |
|---|---|---|---|---|---|
| 原版默认（未改任何 ini） | 1280×720 | **35.5** | 28.15 ms | 18.40 ms | 1.84 GB |
| 原版默认 | 1920×1080 | **27.8** | — | 35.57 ms | — |
| 流畅，不锁帧 | 1280×720 | **84.1** | 11.89 ms | 8.26 ms | 1.59 GB |
| 流畅 + 省内存，不锁帧 | 1280×720 | 75.3 | 13.28 ms | 9.56 ms | 1.58 GB |
| 流畅 + 极省 + 85% 渲染 | 1920×1080 | 78.5 | 12.73 ms | 8.53 ms | 1.62 GB |
| **流畅 + 省内存 + VSync 60（面板默认）** | 1280×720 | **60.00 稳定** | 16.67 ms | 9.96 ms | **1.58 GB** |
| 流畅 + 极省 + VSync 60 | 1280×720 | 60.00 稳定 | 16.67 ms | 8.39 ms | 1.57 GB |

**瓶颈判断（决定哪些优化有用）**：

- 原版默认掉到 35 fps 时，**CPU 侧 28 ms 是主因**，GPU 只要 18 ms。降分辨率救不了——降画质档才能，
  因为它砍的是阴影/后处理这些**每帧都要翻译的命令**，Rosetta 少翻译一层，帧时间直接腰斩。
- 关掉这些之后 GPU 只剩 8~10 ms，**60 fps 有充足余量**，所以面板默认用 VSync 锁 60：
  帧时间曲线是平的（`60.00 [60.00, 60.00]`），机器不烫、风扇不转，比"跑 84 fps 抖着"舒服得多。
- **内存 1.5 GB 是底**。构成大致是：Wine + Rosetta 固定开销 ≈ 0.9 GB，UE4 堆 + CEF ≈ 0.5 GB，
  Metal 纹理 ≈ 0.1~0.2 GB。纹理池 1000→256、mip 偏置、85% 渲染加起来只省十几 MB，
  所以「内存压力」这一项的实际收益是**让长时游玩的池子不继续涨**，不是立刻省下几百 MB。

**还能做的**：关掉其它吃内存的 App；分辨率可以上 1080p（GPU 有余量，`极省` 档在 1080p 也能 78 fps）；
想更省电就把帧率设 30。

> 未验证项：帧率上限的「30」档只写了配置，没有单独实测；1080p 长时游玩（>30 分钟）也没测。
