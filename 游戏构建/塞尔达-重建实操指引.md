# 塞尔达传说 Mac 原生版 —— 从零重建实操指引

> **这份文档只解决一件事**：万一 App 丢了、坏了、或者换了新 Mac，凭这块固态上的东西，把
> 《旷野之息》和《王国之泪》两个 App 一模一样地做回来。
>
> 讲"为什么这么设计"的是 `构建流程.md`（686 行，架构级，在固态
> `/Volumes/SSD/Game/游戏构建/塞尔达/` 里）。这份只讲**动手**：从哪个文件开始、敲哪条命令、
> 怎么确认做对了。
>
> **本文件放在两个地方，内容完全一致：**
> - 本机 `~/Games/游戏构建/重建实操指引.md` ← 盘没插也能看
> - 固态 `/Volumes/SSD/Game/游戏构建/塞尔达/重建实操指引.md` ← 和构建源码放在一起
>
> 注意：本机这个目录里**只有文档**，真正的构建源码（3.1 GB）在固态上。

最后更新：2026-10-27

---

## 0. 先判断你属于哪种情况

| 情况 | 表现 | 走哪一节 | 耗时 |
|---|---|---|---|
| **A. App 只是被删了** | 固态上那份 App 还在，本机没了 | 第 2 节 | 5 分钟 |
| **B. App 坏了 / 想改东西** | App 打不开、画面异常、想调参数 | 第 3 节 | 1~2 小时 |
| **C. 换了新 Mac** | 全新系统，什么都没有 | 第 4 节 | 2~3 小时 |

**九成情况是 A**，根本不用重建。先别急着编译。

### 三样"不可再生"的东西

丢了这三样，就真的重建不了：

1. **游戏本体**：`[0100F2C0115B6000][v0].xci`、`[01007ef00011e000][v0].nsp`
2. **`prod.keys` + `title.keys`**（v22.5.0，`ProdKeys.-v22.5.0/` 里那份）
3. **`游戏构建/塞尔达/_构建源码/Source/`**：整个目录，尤其 `build_app.py` 和 `runtime/`

其余都能重新生成（工作树、着色器缓存、App 本体）。

> **强烈建议**：把这三样再单独拷一份到别的盘或网盘。现在它们只有一份，全在这块固态上。

## 2. 情况 A：App 只是被删了 —— 直接拷回来

**不需要编译。** 固态上那份是完整可运行的。

### 2.1 拷回原位

```sh
mkdir -p ~/Games/旷野之息 ~/Games/王国之泪

# 用 cp -cR 做 APFS 克隆：同卷不额外占空间，跨卷就是普通复制
cp -cR "/Volumes/SSD/Game/塞尔达-Mac版/旷野之息/Breath of the Wild.app" ~/Games/旷野之息/
cp -cR "/Volumes/SSD/Game/塞尔达-Mac版/王国之泪/Tears of the Kingdom M3.app" ~/Games/王国之泪/
```

> 16 GB 的 App 跨卷复制在 USB 3.0 上大约 1~2 分钟。**别中途拔盘。**

### 2.2 去掉隔离标记（从网盘下的包才需要）

```sh
xattr -dr com.apple.quarantine ~/Games/旷野之息/"Breath of the Wild.app"
xattr -dr com.apple.quarantine ~/Games/王国之泪/"Tears of the Kingdom M3.app"
```

从本机拷到移动盘再拷回来一般没有隔离标记，可以先跑 `xattr -l <app>` 看一眼，空的就跳过。

### 2.3 也可以直接在固态上跑

实测可行（2026-10-27 验证）：双击固态上那个 `.app` 就能玩，不用拷回本机。

- 存档仍在内部盘 `~/Library/Application Support/MacNativeGames/{BOTW,TOTK}/`，跟着机器走，不跟着 App 走。
- 固态读取实测 301 MB/s，加载比内置盘慢一点，进游戏后差别不大。
- **玩的时候不能拔盘。**
- ⚠️ 从命令行直接 exec 固态上的二进制（`Contents/MacOS/BotW --play`）会静默退出，**只能用双击 / `open -a`**。内置盘那份没这个问题。

### 2.4 存档要不要恢复

App 和存档是分开的。只拷 App 回来，存档还在，直接读得到。

如果连存档也没了，从 `游戏数据/BOTW`、`游戏数据/TOTK` 拷回去：

```sh
mkdir -p ~/Library/Application\ Support/MacNativeGames
cp -R "/Volumes/SSD/Game/塞尔达-Mac版/游戏数据/BOTW" ~/Library/Application\ Support/MacNativeGames/
cp -R "/Volumes/SSD/Game/塞尔达-Mac版/游戏数据/TOTK" ~/Library/Application\ Support/MacNativeGames/
```

## 3. 情况 B：完整重建

### 3.1 环境准备（只做一次）

```sh
# 1) Xcode 命令行工具
xcode-select --install

# 2) Homebrew 依赖：音频（opus）和预渲染影片（libvpx）是硬依赖，缺了链接会失败
brew install opus libvpx python@3.14

# 3) Python 环境（源码树里已经有一个，可以直接用；新机器要重建）
cd "/Volumes/SSD/Game/游戏构建/塞尔达/_构建源码/Build"
python3.14 -m venv venv
./venv/bin/pip install -r work/totk/requirements.txt
```

> 工作树里的 `Build/work/totk/.venv` 是指向 `../venv` 的**相对**符号链接，整个目录搬到哪里都不会断。
> 如果它断了（`ls -la` 显示指向一个不存在的绝对路径），重建一下即可：
> `cd Build/work/totk && ln -sfn ../venv .venv`
>
> 树里还有一个相对链接 `Build/work/totk/tooling/spirv-cross -> ../../src/SPIRV-Cross`，
> 断了就这样修：`cd Build/work/totk/tooling && ln -sfn ../../src/SPIRV-Cross spirv-cross`

**磁盘空间**：一次完整构建需要 **60 GB 以上空闲**。构建过程会解包 romfs、编译图形层、
生成 16 GB 的 App，全在 `--work` 目录里。

> 建议先把 `_构建源码` 从固态拷到本机再构建 —— 在 USB 上编译慢很多，而且中途拔盘就废了。
> 构建完再把产物拷回固态。

### 3.2 王国之泪：XCI 本体 + 1.4.3 更新

```sh
SRC="/Volumes/SSD/Game/塞尔达-Mac版"                  # 游戏素材（xci/nsp/keys）
BUILD="/Volumes/SSD/Game/游戏构建/塞尔达/_构建源码"   # 构建源码
python3 "$BUILD/Source/build_app.py" \
  "$SRC/王国之泪/素材/xci本体/[0100F2C0115B6000][v0].xci" \
  --update "$SRC/王国之泪/素材/upd-v1.4.3/[UPD][v1.4.3][0100F2C0115B6800][v720896].nsz" \
  -k "$SRC/王国之泪/素材/ProdKeys.-v22.5.0/prod.keys" \
  --work "$HOME/SeldaBuild/totk" \
  -o "$HOME/SeldaBuild/out/Tears of the Kingdom M3.app"
```

关键点：

- `--update` 传的是 **`.nsz`**（压缩格式），脚本原生支持，不用先解压。
- **必须产出 Metal 3 目标**。`build_app.py` 靠环境变量 `TOTK_M3=1` 决定给 make 加不加 `-m3` 后缀；
  不加 `-m3` 编出来的是 Metal 4 目标，**在 macOS 15 上跑不起来**。当前版本脚本默认已按 M3 走，
  日志里会出现一行 `Metal 3 build: minimum system macOS 15.0`，**看到这行才算对**。
- 首次构建约 **55 分钟**（M4 / 16 GB，日志实测 00:15 开始、01:10 结束，其中 107 秒花在 macOS
  对新 App 的一次性校验上）。

### 3.3 旷野之息：NSP 本体 + 1.9.0 更新 + 两个 DLC

```sh
SRC="/Volumes/SSD/Game/塞尔达-Mac版"                  # 游戏素材（xci/nsp/keys）
BUILD="/Volumes/SSD/Game/游戏构建/塞尔达/_构建源码"   # 构建源码
python3 "$BUILD/Source/build_app.py" \
  "$SRC/旷野之息/素材/The Legend of Zelda Breath of the Wild [01007ef00011e000][v0].nsp" \
  --update "$SRC/旷野之息/素材/The Legend of Zelda Breath of the Wild 1.9.0 [01007EF00011E800][v1114112].nsp" \
  --dlc "$SRC/旷野之息/素材/dlc-2/[DLC][01007ef00011f001].nsp" \
  --dlc "$SRC/旷野之息/素材/dlc-2/[DLC][01007EF00011F002].nsp" \
  -k "$SRC/旷野之息/素材/ProdKeys.-v22.5.0/prod.keys" \
  --work "$HOME/SeldaBuild/botw" \
  -o "$HOME/SeldaBuild/out/Breath of the Wild.app"
```

关键点：

- **两个 DLC 都要传**，少传一个那个包就不在 App 里。1.9.0 的 DLC **只认 `--dlc`**，
  即使本体是合并卡带也一样。
- **字体**：NSP 构建需要 6 个共享字体。上次构建日志 `Build/work/logs/shared_fonts.log` 是
  `{"status": "pass", "fonts": [[0,2053628],[1,7814744],[2,106320],[3,3580260],[4,3672868],[5,180236]]}`，
  说明当时提取成功了。**盘上没单独留一份字体目录**，如果重建时报字体缺失：
  - 加 `--firmware <解包的固件 NCA 目录>`，或
  - 加 `--shared-fonts <之前提取好的字体目录>`（里面要有 6 个 `.bfttf`）。
- 构建时间与王国之泪相近。

### 3.4 产物装回去

```sh
cp -cR "$HOME/SeldaBuild/out/Tears of the Kingdom M3.app" ~/Games/王国之泪/
cp -cR "$HOME/SeldaBuild/out/Breath of the Wild.app"     ~/Games/旷野之息/

# 从网盘/别的机器拷来的才需要
xattr -dr com.apple.quarantine ~/Games/王国之泪/"Tears of the Kingdom M3.app"
```

### 3.5 只改了一点点东西？不用全量重建

| 改了什么 | 跑什么 | 耗时 |
|---|---|---|
| `runtime/*.c` / `*.m` | `cd Build/work/totk && make -j$(sysctl -n hw.ncpu) runtime-v143-m3`（旷野是 `runtime-botw190-m3`），把 `build/totk-native-v143-m3` 拷成 App 里的 `Contents/Resources/totk/build/totk-native`，重签 | 2~4 分钟 |
| `app/launcher.m` | 见下面那条单编命令，拷进 `Contents/MacOS/`，重签 | 5 秒 + 重签 |
| 只改界面文字 | 同上 | 秒级 |

启动器单编（两个游戏靠宏区分，输出文件名不同）：

```sh
cd "/Volumes/SSD/Game/游戏构建/塞尔达/_构建源码/Build/work/totk"

# 王国之泪
xcrun clang -fobjc-arc -O2 -Wall -Ithird_party/d2r_gfx/gfx/nvn -Iruntime \
  -DTOTK_GAME_V143=1 app/launcher.m \
  -framework AppKit -framework GameController -o build/app-launcher-totk

# 旷野之息
xcrun clang -fobjc-arc -O2 -Wall -Ithird_party/d2r_gfx/gfx/nvn -Iruntime \
  -DGAME_BOTW190=1 app/launcher.m \
  -framework AppKit -framework GameController -o build/app-launcher-botw
```

装回去并重签：

```sh
cp build/app-launcher-totk ~/Games/王国之泪/"Tears of the Kingdom M3.app/Contents/MacOS/TOTK"
cp build/app-launcher-botw ~/Games/旷野之息/"Breath of the Wild.app/Contents/MacOS/BotW"

codesign --force --deep --sign - ~/Games/王国之泪/"Tears of the Kingdom M3.app"
codesign --force --deep --sign - ~/Games/旷野之息/"Breath of the Wild.app"
```

> ⚠️ **改任何二进制都必须重签**，否则 App 起不来。
> `--deep` 对 16 GB 的 App 要约 60 秒，前台跑容易被打断 —— 放后台。
> 只换了启动器、`Contents/Helpers` 里那份数据包没动的话，可以不加 `--deep`，只签本体，几秒完成。

## 4. 情况 C：换一台新 Mac

前提：**Apple Silicon（M 系列），macOS 15.0 或更新**。Intel Mac 跑不了。

顺序：

1. 按 **3.1** 装好 Xcode CLT、Homebrew 依赖、Python 环境。
2. 按 **2.1** 从固态把两个 App 拷到 `~/Games/...`。
3. 按 **2.2** 去掉隔离标记。
4. 按 **2.4** 把 `游戏数据/{BOTW,TOTK}` 拷到 `~/Library/Application Support/MacNativeGames/`。
   **不拷这一步游戏能开，但没有存档。**
5. 第一次启动会重新预热着色器（几分钟），属正常现象 —— 着色器缓存是跟机器走的，换机必须重建。

> 以上 5 步做完就能玩了，**不需要碰 `游戏构建/`**。
> 只有新机器上要重新编译时，才把 `/Volumes/SSD/Game/游戏构建/塞尔达/` 整个拷过去
> （`_构建源码` 3.1 GB + 两份文档），然后按第 3 节走。路径随便放，只要 `Build/work/totk/.venv`
> 这个相对链接不断就行。

> `~/Library` 默认隐藏：Finder 里按 `Shift+Cmd+G` 粘贴路径即可进入。

## 5. 验收：怎么确认"和原来那个一模一样"

**不用开游戏**就能查前两项。

```sh
APP=~/Games/旷野之息/"Breath of the Wild.app"

# 1) 版本自检 —— 几秒返回，应该打印 ok: game version 1.9.0
"$APP/Contents/MacOS/BotW" --check

# 2) 签名
codesign -dv "$APP" 2>&1 | grep -E "Identifier|Signature"
#   旷野之息 → Identifier=org.macnativegames.botw   Signature=adhoc
#   王国之泪 → Identifier=org.macnativegames.totk   Signature=adhoc

# 3) 校验签名完整性（慢，16 GB，可跳过）
codesign --verify --strict "$APP"
```

真要确认画面，开一次游戏，看日志里这两行：

```sh
tail -f ~/Library/Logs/MacNativeGames/botw.log     # 王国之泪是 totk.log
```

- `[totk-gfx] [shader-seed] 发现随 App 准备的着色器 N 个，导入 0 个文件；首次启动即可预热`
  → 着色器种子身份对上了（旷野之息约 11947 个，王国之泪约 8290 个）
- `出图节拍 60 Hz，间隔模式 game（原版语义）` → 出图节拍正常

最后确认存档能读：进游戏 → 继续游戏 → 能看到存档槽。

## 7. 已知的坑（会真的卡住你）

| 坑 | 现象 | 处理 |
|---|---|---|
| **中文路径** | 启动器白窗口、几十秒后静默退出 | App 必须放纯英文路径。`~/Games/旷野之息/` 这种目录名没问题，但**别再往里面套中文子目录** |
| **少了 `-m3`** | 编译能过，macOS 15 上启动即崩 | 确认构建日志里有 `Metal 3 build: minimum system macOS 15.0` |
| **改了二进制没重签** | App 双击没反应 | `codesign --force --deep --sign - <app>` |
| **`--deep` 超时** | 命令被中断，签名不完整 | 放后台跑；只换启动器时可不加 `--deep` |
| **构建中断在解包阶段** | 工作树残留半成品，重跑报错 | 删掉 `--work` 目录重来。素材不受影响 |
| **DLC 少传一个** | 游戏里那个 DLC 内容不存在 | 两个 `--dlc` 都要传 |
| **字体缺失** | 构建报 shared fonts 相关错误 | 见 3.3 的字体说明 |
| **在 USB 上直接构建** | 慢 3~5 倍，拔盘即废 | 先拷 `_构建源码` 到本机 |
| **符号链接断了** | `make` 报找不到 SPIRV-Cross / venv | 树里有 2 个相对链接，搬动时**别用 `cp -RL`**（会解引用）。断了就重建，见 3.1 |
| **固态上命令行 `--play`** | 静默退出，无窗口 | 用双击 / `open -a` |
