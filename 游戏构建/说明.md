# 游戏构建归档

这里收的是**所有"重新做一遍"需要的东西**。日常玩游戏不用进来。

> **本文件放在两个地方，内容完全一致：**
> - 本机 `~/Games/游戏构建/说明.md` ← 盘没插也能看
> - 固态 `/Volumes/SSD/Game/游戏构建/说明.md` ← 和全部构建源码在一起
>
> **两边都有什么**：七份分文档 + `总重建指引.md` + 本文件 + 两个脚本 + 五套 `_build` 源码（几百 KB）。
> **只有固态有的**：塞尔达那 3.1 GB 构建源码 / 工作树、以及各游戏 App 本体和原始 dmg。
>
> 改完任何一份文档或 `_build` 里的源码，跑一次 `bash _同步到本机.sh`，两边就一致。


## 三、不可再生的东西

丢了就真做不回来了，建议再单独备份一份到别的盘或网盘：

1. **游戏本体**：`塞尔达-Mac版/王国之泪/素材/xci本体/[0100F2C0115B6000][v0].xci`（17.5 GB）
   和 `塞尔达-Mac版/旷野之息/素材/The Legend of Zelda Breath of the Wild [01007ef00011e000][v0].nsp`（14.5 GB）
2. **密钥**：两份 `ProdKeys.-v22.5.0/` 里的 `prod.keys` + `title.keys`
3. **源码**：`塞尔达/_构建源码/Source/`（24 MB）

其余（工作树、着色器缓存、App 本体）都能重新生成。

霍格沃茨之遗这边唯一"不可再生"的是 **`HogwartsLegacy/_installer/` 里的原始 dmg（88 GB）**——
它是从第三方站下的 v1613387，丢了不一定还能找到同一个版本。App 本身随时可以从它重装（40 分钟）。

港诡实录的原始 dmg（`港诡实录+Paranormal+HK+v1.04+[www.getmacapp.com].dmg`，7.4 GB）同理：**别删**。
App 本身改造过（换启动器 + 改 Info.plist + 补 libinotify 符号链接），
dmg 是唯一的干净底本。

鬼泣4 也一样：固态根下 `鬼泣4 Devil May Cry 4 Special Edition v20230105 [www.getmacapp…].dmg` 是干净底本。
另外 `App/Contents/SharedSupport/prefix/drive_c/…/nativeDX10/` 那 25 GB 是游戏资源本体，
**删了就补不回来**（除非重新解 dmg）。

## 四、搬动时的注意事项

- 树里有 **2 个相对符号链接**，搬动时**别用会解引用的方式复制**（比如 `cp -RL`、Finder 拖拽），
  会把 venv 复制成一堆实体文件、把 SPIRV-Cross 复制成两份：
  - `_构建源码/Build/work/totk/.venv` → `../venv`
  - `_构建源码/Build/work/totk/tooling/spirv-cross` → `../../src/SPIRV-Cross`

  正确做法：`ditto`、`cp -R`（保留链接）或 `rsync -a`。搬完自检一遍：

  ```sh
  find "/Volumes/SSD/Game/游戏构建" -type l | while read l; do [ -e "$l" ] || echo "断链: $l"; done
  ```
- 在 USB 上直接构建慢 3~5 倍，且中途拔盘即废。要重建的话先拷到本机。
- 构建产物是 16 GB 的 App，加中间文件需要 **60 GB 以上空闲**。
- 港诡实录的路径**不能带中文**：Wine 转成 `????` 之后 wine 找不到 exe。
  所以盘上是 `ParanormalHK/Paranormal HK.app`，不是 `港诡实录.app`；要显示中文靠 `Info.plist` 里的 `CFBundleName`。

| 场景 | FPS | GPU | CPU 侧 Pre | 内存 |
|---|---|---|---|---|
| 主菜单 | 60（被 t.MaxFPS 钉住） | 12.7 ms | 22.5 ms | 9.0 GB |
| 室内 | 56 | 12.6 ms | 24.1 ms | 13.8 GB |

- 游戏进程峰值 footprint **11.8 GB**；`footprint` 分类：IOAccelerator 2483 MB / UE 堆 1645 MB /
  WINE_RESERVE 1395 MB / 匿名映射 1373 MB / Rosetta 系 629 MB —— **只有第一项可压**
- 外置盘 USB 5 Gb/s，顺序读 **403 MB/s**；运行时读盘 4–20 MB/s（占带宽 1–6%）→ **磁盘不是瓶颈**
- 启动器面板本身只占 21 MB，启动游戏后释放 UI 降到 ~10 MB
- **瓶颈结论**：GPU 只吃 12/16.7 ms，CPU 侧 Pre 更长 → Rosetta 2 + D3DMetal 命令翻译；
  "卡一下"来自 16 GB 内存吃满、swap 打满。**降画质/降分辨率无效。**
- **GPTK 4（D3DMetal 4）需要 macOS 26+（Metal 4）**，本机 macOS 15.6 用不了；
  它的收益是帧率（+10~25%）不是内存，且报告称每次启动要等约 20 分钟着色器编译。

**实测基线**

| 配置 | 分辨率 | FPS | Pre（CPU） | GPU | 内存 |
|---|---|---|---|---|---|
| 原版默认 | 1280×720 | 35.5 | 28.15 ms | 18.40 ms | 1.84 GB |
| 原版默认 | 1920×1080 | 27.8 | — | 35.57 ms | — |
| 流畅，不锁帧 | 1280×720 | 84.1 | 11.89 ms | 8.26 ms | 1.59 GB |
| 流畅 + 省内存，不锁帧 | 1280×720 | 75.3 | 13.28 ms | 9.56 ms | 1.58 GB |
| 流畅 + 极省 + 85% 渲染 | 1920×1080 | 78.5 | 12.73 ms | 8.53 ms | 1.62 GB |
| **流畅 + 省内存 + VSync 60（面板默认）** | 1280×720 | **60.00 稳定** | 16.67 ms | 9.96 ms | **1.58 GB** |
| 流畅 + 极省 + VSync 60 | 1280×720 | 60.00 稳定 | 16.67 ms | 8.39 ms | 1.57 GB |

- 瓶颈：默认 35.5 fps 时 **CPU 28.15 ms > GPU 18.40 ms** → Rosetta 指令翻译 + D3DMetal 命令翻译。
  降分辨率基本无效（1080p 只掉 8 帧），**降画质档有效**（84 fps）。
- 内存从 1.84 GB 压到 **1.57–1.58 GB 就见底了**，再往下压不动：
  Wine + Rosetta ≈ 0.9 GB、UE4 堆 + CEF ≈ 0.5 GB、Metal 纹理 ≈ 0.1–0.2 GB，
  纹理池 1000→128 MB 加 85% 渲染总共只省十几 MB。
  **省内存档的真正收益是让长时游玩的池子不继续涨，不是立刻省几百 MB。**
- 观帧率只能靠 `MTL_HUD_ENABLED=1`（UE4 Shipping 没控制台），HUD 显示在游戏窗口内，
  截图要用 `screencapture -l <windowid>` 抓窗口，全屏截会被遮挡。

## 七、每次构建完的留存流程（照做，别偷懒）

**规矩：一次游戏构建/调优结束，必须同时做到三件事 —— 固态留档、本机留档、总文档更新。**

```
① 改分文档            游戏构建/<游戏名>/重建实操指引.md（工作副本，在这一份上改）
② 把 _build 源码归档   新建/修改的 .m .sh .c 都放进 游戏构建/<游戏名>/_build/
③ 跑一条命令          bash /Volumes/SSD/Game/游戏构建/_生成总文档.sh
```

`_生成总文档.sh` 一条命令干完后面全部：

1. 把四份分文档拼成 `总重建指引.md`（判别表 + 通用规矩 + 各游戏原文），缺哪份会告警；
2. 覆写固态 `游戏构建/总重建指引.md`，同时留一份到 `/Volumes/SSD/总重建指引.md`；
3. 自动调 `_同步到本机.sh`，把**七份文档 + 总文档 + 说明.md + 两个脚本 + 五套 `_build` 源码**
   镜像到 `~/Games/游戏构建/`，并打印同步了多少个文件、本机目录占多大。

正常输出长这样（数字会变）：

```
已生成：/Volumes/SSD/Game/游戏构建/总重建指引.md
行数：1833
大小：100876 字节
已同步 27 个文件 → /Users/wilkins-/Games/游戏构建
本机游戏构建目录占用：476K
```

**校验两边是否真的一致**（改了文档却忘了跑脚本时，这一步能抓出来）：

```sh
cd "/Volumes/SSD/Game/游戏构建"
shasum 说明.md "$HOME/Games/游戏构建/说明.md"
shasum 总重建指引.md "$HOME/Games/游戏构建/总重建指引.md"
# 两行哈希值必须相同
```

**只有固态有的东西**（本机不放）：塞尔达 `_构建源码/`（3.1 GB 工作树）、各游戏 App 本体、原始 dmg。
本机存的只是「拔了盘还能查文档、还能重编启动器」那部分，总共不到 500 KB。

> 新增游戏时的固定动作：在 `游戏构建/` 下建 `<游戏名>/` 与 `<游戏名>/_build/`，
> 写 `重建实操指引.md`，然后改 `_生成总文档.sh`（加 `SRC_xxx` 变量、缺文档告警、第 N 部分输出块、
> 判别表行、游戏一览行、附录清单）和 `_同步到本机.sh`（加 take 行），最后跑一次生成脚本。
