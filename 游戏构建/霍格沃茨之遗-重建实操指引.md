## 第 0 节 · 情况判别表（先看这里，九成不用重建）

## 第 3 节 · 从零重建（App 整个没了才需要）

### 3.1 准备

- 空闲空间：**≥ 200 GB**（dmg 88 GB + 解出来的 app 92 GB）
- 目录必须是**纯英文路径**。中文路径会让 Wine 把路径转成 `????`，`wine.inf` 更新失败。本机用的是 `/Volumes/SSD/Game/HogwartsLegacy/`
- 时间：全程约 40 分钟（dmg 挂载 + 拷贝最慢，外置 USB 盘写入会从 400 MB/s 掉到 45~60 MB/s）

### 3.2 装出原始 app

```sh
cd /Volumes/SSD/Game/HogwartsLegacy
hdiutil attach "_installer/霍格沃茨之遗 Hogwarts Legacy v1613387 [www.getmacapp.com].dmg"
# 挂载点里把 "Hogwarts Legacy.app" 拖/拷到当前目录
ditto "/Volumes/<挂载卷>/Hogwarts Legacy.app" "./Hogwarts Legacy.app"
hdiutil detach "/Volumes/<挂载卷>"
```

装完先**双击试一次**：会报 `SikarugirSdk.FileUtilsError error 1`（"Folder not found or could not be enumerated"）—— 这是原厂启动器在 macOS 15 上的 bug，正常，接下来就把它换掉。

### 3.3 换成 GPTK 3.0-3 渲染层

原厂自带的是 GPTK 17 版，必须换 3.0-3，否则 D3D12 初始化不过。

三个组件，**换之前先改名备份成 `*.orig17`**（本机已经这么做了，所以现在直接跳过这步）：

```sh
R="Hogwarts Legacy.app/Contents/Frameworks/renderer/d3dmetal"
# 1) D3DMetal.framework
# 2) external/libd3dshared.dylib
# 3) wine/x86_64-windows（整个目录）
```

GPTK 3.0-3 从 Gcenx 的 `apple-gptk` 分发里取，校验 `D3DMetal` 二进制 sha256 应与分发一致。

### 3.4 修 bundle 里三个必坏的配置

```sh
APP="/Volumes/SSD/Game/HogwartsLegacy/Hogwarts Legacy.app"
SUP="$APP/Contents/SharedSupport"

# ① libinotify 缺失 → wineserver 起不来
ln -sf ../../../Frameworks/libinotify.0.dylib "$SUP/wine/lib/libinotify.0.dylib"

# ② dosdevices 里打包者自己机器的盘符是断链，只留 c: 和 z:
ls "$SUP/prefix/dosdevices/"     # 正常只有 c:  z:
rm -f "$SUP/prefix/dosdevices/d:" "$SUP/prefix/dosdevices/d::" \
      "$SUP/prefix/dosdevices/e:" "$SUP/prefix/dosdevices/e::"

# ③ 自检断链
find "$APP" -type l | while read l; do [ -e "$l" ] || echo "断链: $l"; done
```

### 3.5 编译并安装启动器（这一步决定能不能双击玩）

```sh
bash "/Volumes/SSD/Game/游戏构建/霍格沃茨之遗/_build/build_launcher.sh"
```

脚本会同时装 `hl_mouse`（鼠标锁定辅助进程）并 ad-hoc 签名。手工装的话：

```sh
clang -fobjc-arc -O2 -framework AppKit -framework Carbon -o /tmp/hl_mouse _build/hl_mouse.m
codesign --force --sign - /tmp/hl_mouse
ditto --norsrc /tmp/hl_mouse "$APP/Contents/MacOS/hl_mouse"; chmod 755 "$APP/Contents/MacOS/hl_mouse"
xattr -c "$APP/Contents/MacOS/hl_mouse"
```

`hl_mouse` 的行为：
- **默认锁定**：窗口一出现就把光标锁在窗口内（`CGWarpMouseCursorPosition` + `CGAssociateMouseAndMouseCursorPosition(false)` + `CGDisplayHideCursor`）；
- **按 0 切换**：脱离 → 普通系统光标、可去桌面；再按 0 锁回。热键是**全局注册**的（和塞尔达一样），
  游戏运行期间 `7` 会被系统吃掉；不要就在面板里取消勾选。
- 热键注册失败时**不自动锁定**（否则没有解锁手段），日志会写明；
- 游戏进程退出 / SIGTERM / SIGHUP 都会先解锁再退，**绝不会把鼠标锁死**；
- `kill -USR1 <pid>` 等价按一次 0，方便脚本调试。
- **不要**改成"按前台 App 自动解锁"：实测 `NSWorkspace.frontmostApplication` 在 Wine 窗口上会抖，
  锁/解锁每秒来回切（踩过）。

脚本里已经封好了三条硬规矩，**别手工改成 `cp`**：

1. **编译输出必须直接叫 `/tmp/Sikarugir`**。ad-hoc 签名的 identifier 由文件名派生，叫 `hl_launcher` 会得到 `hl_launcher-<uuid>`，与 bundle 里的文件名不一致 → 系统判签名无效。
2. **先签名、再拷进 bundle**。在 bundle 内签会触发 `ResourceBuilder::scan` 扫 92 GB（16 分钟且失败，因为 `Contents/Cheat Engine.app` 未签名）。
3. **拷进去必须 `ditto --norsrc` + `xattr -c`**。实测用 `cp -f` 覆盖同一个路径后，系统会判 `SIGKILL (Code Signature Invalid)` / `Taskgated Invalid Signature`，表现是双击完全没反应，只在 `~/Library/Logs/DiagnosticReports/` 里留一份 `bug_type 309` 报告。换 `ditto` 就正常（顺带清一下扩展属性更保险）。

### 3.6 首次运行

```sh
open -a "/Volumes/SSD/Game/HogwartsLegacy/Hogwarts Legacy.app"
```

会依次发生：

1. 弹「**想要访问可移除宗卷上的文件**」→ **点允许**（一次性，之后不再问）
2. 出现「霍格沃茨之遗 Mac — 启动设置」面板
3. 点「启动游戏」→ 黑窗口 →「正在准备着色器」（**冷缓存 10 分钟起，进度条长时间不动是正常的**）
4. 标题画面「按任意键开始」→ 主菜单 → 载入存档

> 如果双击完全没反应、也没有 TCC 弹窗：先看 `~/Library/Logs/DiagnosticReports/` 有没有新的 `Sikarugir-*.ips`。
> 有 → 签名问题，回 3.5 重装。没有 → 残留 Wine 进程，跑第 0 节的 `pkill`。

面板会自动写。想手工核对，两个文件：

**`Engine.ini`** —— 末尾要有 `[SystemSettings]` 段：

```ini

r.Streaming.MaxTempMemoryAllowed=32
r.Streaming.LimitPoolSizeToVRAM=1
r.Streaming.DefragDynamicBounds=1

r.SSR.HalfResSceneColor=1
r.VolumetricFog=0
r.AmbientOcclusionLevels=0
r.DepthOfFieldQuality=0
r.MotionBlurQuality=0
r.LensFlareQuality=0
r.SceneColorFringeQuality=0
r.MaxAnisotropy=1
r.GPUCrashDebugging=0
```

**`GameUserSettings.ini`** —— 三段：

```ini
[/Script/Phoenix.PhoenixGameSettings]
ResolutionSizeX=1280
ResolutionSizeY=720
LastUserConfirmedResolutionSizeX=1280
LastUserConfirmedResolutionSizeY=720
FullscreenMode=2                 ; 0=独占全屏 1=无边框全屏 2=窗口
LastConfirmedFullscreenMode=2

[ScalabilityGroups]
sg.ResolutionQuality=100
sg.ViewDistanceQuality=0
sg.AntiAliasingQuality=1
sg.ShadowQuality=0

sg.TextureQuality=0
sg.EffectsQuality=0
```

> 自己另写脚本时注意。

## 第 4 节 · 启动器面板

源码 `_build/hl_launcher.m`（约 600 行，AppKit，无 nib）。结构照抄塞尔达那个启动器：

```
label:frame:size:bold:color:   check:frame:on:   button:frame:action:key:   separator:
buildWindow  → 摆控件
loadSettings → 读 launcher-settings.json
saveSettings → 写 JSON
applyIni     → 写 Engine.ini / GameUserSettings.ini
startGame    → setenv + chdir + fork/execv wine
```

**面板选项 → 落到哪里**：

| 面板项 | 落到 |
|---|---|
| 分辨率 / 窗口模式 / VSync | `GameUserSettings.ini` → `[/Script/Phoenix.PhoenixGameSettings]` |
| 画质档（最低/中/高） | `GameUserSettings.ini` → `[ScalabilityGroups]` 的 `sg.*`（0/1/2） |
| 锁帧 | `Engine.ini` → `t.MaxFPS`（0 = 不限） |
| 内存模式 | `Engine.ini` → `r.Streaming.PoolSize`（1024/768/512）+ `r.Shadow.MaxCSMResolution`（1024/512）；`GameUserSettings.ini` → `sg.ResolutionQuality`（100/85/70） |
| 精简渲染 | `Engine.ini` → SSR/体积雾/景深/动态模糊/各向异性 那一组（关掉 = 删键） |
| Metal HUD | 环境变量 `MTL_HUD_ENABLED=1` |
| Wine 日志 | 环境变量 `WINEDEBUG=err+all`（否则 `-all`） |
| 屏蔽驱动警告 | 环境变量 `D3DM_VENDOR_ID=0x1002` |
| 鼠标锁定 | 启动 `Contents/MacOS/hl_mouse <wine pid>`（按 0 切换 `CGAssociateMouseAndMouseCursorPosition`） |
| CPU 拓扑 | 环境变量 `WINE_CPU_TOPOLOGY=4:0,1,2,3` 或 `10:0..9` |

**跳过面板**：`open -a "Hogwarts Legacy" --args --play`

## 第 5 节 · 环境变量全表（启动器会自动设，手工排查时对照）

| 变量 | 值 | 作用 / 不加会怎样 |
|---|---|---|
| `WINEPREFIX` | `<app>/Contents/SharedSupport/prefix` | 必需 |
| `CX_D3DMETALPATH` | `<app>/Contents/Frameworks/renderer/d3dmetal` | D3DMetal 接线 |
| `CX_APPLEGPT_LIBD3DSHARED_PATH`<br>`CX_APPLEGPTK_LIBD3DSHARED_PATH` | `…/d3dmetal/external/libd3dshared.dylib` | 同上 |
| `DYLD_FRAMEWORK_PATH` | `…/d3dmetal/external:<app>/Contents/Frameworks` | **少 `Contents/Frameworks` 会没有字体** |
| `DYLD_FALLBACK_LIBRARY_PATH` | `…/external:<app>/Contents/Frameworks:<sup>/wine/lib` | **同上，这就是"小横条"的根因** |
| `WINEDLLPATH_PREPEND` | `…/d3dmetal/wine` | D3D 转译 dll 优先 |
| `D3DMETAL` | `1` | 启用 D3DMetal |
| `D3DM_ENABLE_METALFX` | `1` | 允许 MetalFX（游戏不一定会用） |
| `D3DM_VENDOR_ID` | `0x1002` | **伪装成 AMD，去掉驱动警告** |
| `WINEESYNC` / `WINEMSYNC` | `1` | 同步原语加速 |
| `WINE_CPU_TOPOLOGY` | `4:0,1,2,3` | **必须设，去掉会崩** `EXCEPTION_ACCESS_VIOLATION` |
| `WINEDEBUG` | `-all` | 关日志。开 `err+all` 会明显掉帧 |

**绝对不要加的三个**（都会在「准备着色器」阶段崩 `EXCEPTION_ACCESS_VIOLATION reading address 0x00000001e702000b`）：

```
D3DM_BOUNDS_CHECK=0
D3DM_ALLOW_HOOKING=0
D3DM_ENABLE_ASYNC_COMMIT=1
```

## 第 6 节 · 坑位清单（重建时最容易踩的，按严重程度排序）

1. **中文路径** → Wine 转成 `????`，`wine.inf` 更新失败，prefix 建不起来。目录必须纯英文。
2. **`DYLD_FALLBACK_LIBRARY_PATH` 少了 `Contents/Frameworks`** → 找不到 `libfreetype.6.dylib` → **所有窗口客户区塌成 0** → 启动时的对话框变成 6×54 的空壳（"小横条"）→ 点不动 → 游戏永远卡在等它。日志里会有十几条 `Wine cannot find the FreeType font library`。这是本机折腾最久的一个坑。
3. **`WINE_CPU_TOPOLOGY` 不能省** → 崩溃。
4. **三个 `D3DM_*` 开关不能加** → 崩溃。
5. **强杀游戏会留下 Wine 服务进程** → `services.exe` / `winedevice.exe` / `plugplay.exe` / `svchost.exe` 的**命令行里没有路径**（只有 `C:\windows\system32\services.exe`），`pkill -f "SharedSupport/wine"` 抓不到。它们占着 prefix，下次启动就卡在 `wineboot --init`（wine 进程只有 5 MB / 4 线程、不加载任何图形库）。清理用 `pkill -9 -f 'windows.system32'`。
6. **shell 脚本不能当 app 的主可执行文件** → LaunchServices 会把 app 记成"常驻运行"，之后 `open -a` / 双击只会去"激活"它，报 `Application ... was already running and so the additional environment variables could not be set`。必须用真 Mach-O。
7. **主程序必须用 `ditto` 安装，别用 `cp`**（见 3.5）。`cp -f` 覆盖后会被判签名无效、双击无反应。
8. **编译输出必须叫 `/tmp/Sikarugir`**（见 3.5）。
9. **TCC 授权**：外置盘上的 app 首次双击要授权「可移除宗卷」。从终端跑则走终端的 FDA 权限、不弹窗 —— 所以"终端能跑、双击不行"是正常现象，不是坏了。
10. **注册表改 `DriverVersion` 没用**。注册表里 `DriverDesc` 早就被游戏自己改成 `Apple M4` 了，照样弹警告 —— 它看的是 D3DMetal 报的厂商/版本。只有 `D3DM_VENDOR_ID` 有效。
11. **`AGX: exceeded compiled variants footprint limit`** 是良性警告，正常跑通时也会出现，不用管。
12. **vkd3d-proton 这条路走不通**（别再试）：MoltenVK 能跨过 Vulkan 1.3 门槛，但 vkd3d-proton 2.13/3.0.1 都硬性要求 `VK_EXT_transform_feedback`，**Metal 没有 stream output，MoltenVK 不提供**，报 `Lacking support for transform feedback` 后销毁设备退出。
13. **启动器开锁文件必须带 `O_CLOEXEC`**。不加的话 `auto_dismiss.py` / `caffeinate` / `hl_mouse` 会继承这个 fd，
    启动器退出后锁还被它们占着 → 下次双击被误判成"游戏已经在运行了"直接退出（表现为点了完全没反应）。
    正确写法：`open(lockp, O_WRONLY | O_CREAT | O_CLOEXEC, 0644)`。
14. **辅助进程要能自己收工**。`auto_dismiss.py` 原来只等窗口名含 `Hogwarts Legacy`，
    但有时窗口名是 `HogwartsLegacy`（没空格），于是它会一直挂着。已加 `os.kill(pid, 0)` 检测：
    游戏进程没了就退出。
15. **启动器启动游戏后要释放 UI**：`self.window.contentView = nil; self.window = nil;` + 把控件置 nil +
    切 `NSApplicationActivationPolicyProhibited`，进程从 21 MB 降到 ~10 MB，只留一个 `waitpid`。

### 7.1 导入 Epic / Steam 的存档（2026-10-29 实测）

**实际路径**（本机，用户名是 `wilkins-`）：

```

```

`19627` 是平台用户 ID 目录，**别改这个文件夹名**。里面就三类文件：

4. `open -a "Hogwarts Legacy.app" --args --play`，主菜单应该能直接看到角色和等级。

**兼容性怎么判断**（这次实测）：两边都是 UE4 `GVAS` 存档，

> 解析思路：读 `GVAS` 头 → engine version → custom version 数组（GUID + int），逐项对比。

## 第 9 节 · 性能基线与调优边界

**实测数据（1280×720，画质最低，2026-10-28）**：

| 场景 | FPS | GPU 耗时 | CPU 侧 Pre | 内存 |
|---|---|---|---|---|
| 主菜单 | 60（被 `t.MaxFPS` 钉住） | 12.7 ms | 22.5 ms | 9.0 GB |
| 载入中 | 35 | 11.1 ms | 22.7 ms | 10.6 GB |
| 室内（宿舍） | 56 | 12.6 ms | 24.1 ms | 13.8 GB |

**瓶颈判断（重要，决定了哪些优化有用）**：

- GPU 只吃掉 12 / 16.7 ms，**CPU 侧 Pre 更长** → 瓶颈是 Rosetta 2 指令翻译 + D3DMetal 命令翻译。**降画质、降分辨率基本无效。**
- 游戏进程峰值 footprint **11.8 GB**，机器 16 GB；`swap 3279M/4096M`、`Pages wired ≈5.6 GB`（Metal/内核不可换出）→ **swap 打满才是"卡一下"的真因**。
- **磁盘不是瓶颈**：外置固态 USB 5 Gb/s、顺序读 403 MB/s；运行时读盘量主菜单 0 MB/s、游戏内 4–20 MB/s、着色器准备 26 MB/s，全程占带宽 1–6%。换内置 NVMe 不会更快。

**还能做的**：关掉其它吃内存的 App（收益最大）、内存模式选「省内存」、锁帧 30 求"绝对均匀"、分辨率可以上 1080p（GPU 有余量）。

**内存构成（`footprint` 实测，8.26 GB 时点）**：

| 分类 | 占用 | 能不能压 |
|---|---|---|
| IOAccelerator（Metal 显存） | 2483 MB | 能 —— 内存模式压的就是这块 |
| MALLOC_SMALL（UE 堆） | 1645 MB | 不能 |
| WINE_RESERVE | 1395 MB | 不能 |
| untagged VM_ALLOCATE | 1373 MB | 不能，随载入内容增长 |
| Rosetta JIT + Generic + IndirectBranch | 629 MB | 不能 |
| MALLOC_TINY / MEDIUM | 597 MB | 不能 |

**能被参数压下去的只有第一行**，其余 9 GB 是 UE 堆 + Wine + Rosetta 的固定成本。
所以"大幅降内存"做不到；面板的三种内存模式实测能省几百 MB 量级。
启动器自身只占 21 MB（启动后释放 UI 掉到 10 MB），不是内存问题的来源。

## 第 11 节 · 全屏与鼠标锁定（2026-10-29 实测）

### 11.1 全屏模式怎么选（2026-10-29 更正）

**结论：这套 Wine/D3DMetal 下，任何全屏都会闪 / 黑屏，只能用窗口模式。**

| 模式 | 结果 |
|---|---|
| **窗口（唯一稳定）** | 稳定，带标题栏 |
| 无边框全屏 | **会闪 / 黑屏**（D3DMetal 全屏交换链问题） |
| 独占全屏 | **会闪 / 黑屏** |

启动器已强制 `-windowed`（`hl_launcher.m` 的 `argv`），**不要**在游戏里再切全屏。
窗口分辨率由游戏自己的 `SavedUserOptions.sav` 决定（实测 1600x900），
`GameUserSettings.ini` / `-ResX` 不一定压得住。

### 11.2 菜单栏 / Dock 为什么会被划出来

Wine 的全屏窗口在 **layer 26**，旧版 `hl_mouse` 只找 layer 0 → 找不到 → 不锁光标 →
光标自由 → 划到边缘触发菜单栏/Dock（看起来像“闪”）。

### 11.3 hl_mouse 现在的行为

- 找游戏 PID 的**任意 layer** 窗口，取面积最大的。
- 锁定：`CGAssociateMouseAndMouseCursorPosition(false)` + `CGDisplayHideCursor`。
- 钳制 = **窗口 ∩ 屏幕**，四周留 8px；越界只钳到最近的边，**不甩回中心**。
- 按 `0` 解锁/锁回。
- **不要**为了全屏去把 Dock/菜单栏设成自动隐藏（会改用户桌面，且没必要）。

### 11.4 光标被锁死 / 看不见

`hl_mouse` 收到 SIGTERM/SIGINT/SIGHUP 会先解锁，**别用 `kill -9`**。
锁死了就执行：

```c
CGAssociateMouseAndMouseCursorPosition(1);
CGDisplayShowCursor(kCGDirectMainDisplay);   // 多调几次
```

或 `killall Dock; killall Finder` 重启桌面。

### 11.5 人物外观 mod（GitHub / Nexus）

- **GitHub 几乎没有外观 mod**：主要是工具/修改器（`UE4SS-RE/RE-UE4SS`、`Lyall/HogwartsLegacyFix` 超宽屏修复），以及法术解锁/作弊仓库（注意风险）。
- 外观 mod 去 **Nexus Mods** 或 **3DM Mod站**：
  - `https://www.nexusmods.com/hogwartslegacy`
  - `https://mod.3dmgame.com/HogwartsLegacy`


  没有 `~mods` 就新建；放 `.pak`（配套 `.ucas`/`.utoc` 一起）。

## 第 12 节 · 怎么判断一个 mod 能不能用（2026-10-30）

### 12.1 先搞清版本坐标：v1613387 就是官方最新版

这点以前搞错过，记下来别再错：

- `v1613387` 对应 **Steam BuildID 20773316**，是官方 **2025-12-03 的 PC 热修**
- 这一版的核心内容就是**修 Mod 系统**（官方在此之前给 PC 加了原生 Mod 支持）
- 所以「mod 不兼容」不是游戏太旧，而是**老 mod 太老**：Tifa 826 / Draco / Emma 都是
  2023 年首发版做的，中间隔了两年多、十几次内容更新

**推论：没有「升级游戏就能用老 mod」这条路，只有「找匹配这个版本的 mod」。**

### 12.2 这版自带官方 CurseForge mod 支持

主 exe（`Phoenix/Binaries/Win64/HogwartsLegacy.exe`，450 MB）里能查到：

```
/Script/GameModManagerShim
CurseForgeLinked
m_curseForgeLink
WBPNCurseForgeSilentAuthTokenResponse
```

也就是说游戏内有官方 Mod 浏览器（走 CurseForge），里面装的 mod 是**按版本自动匹配**的，
比手动往 `~mods` 丢 `.pak` 稳得多。⚠️ 但它是网页组件，Wine 下能不能正常打开要实测。

### 12.3 Nexus 没有「游戏版本」筛选，用这三个判据代替

Nexus 只有部分游戏提供 version 过滤，霍格沃茨之遗没有。所以只能靠：

| 判据 | 怎么用 |
|---|---|
| **更新时间** | v1613387 = 2025-12-03。**只有 2025-12 之后更新的 mod 才可能匹配**；2023–2024 的基本都废了。Nexus 可以按 `Last updated` 排序 |
| **作者说明里的 patch 号** | 有些作者会写 "for 1.0.0.1613387" |
| **文件类型** | 纯 legacy `.pak` 跨版本兼容性好一些；`.ucas/.utoc`（IoStore）必须版本精确匹配 |

### 12.4 下载后用 `_build/check_mod.py` 预检（10 秒出结论）

```sh
cd "/Volumes/SSD/Game/游戏构建/霍格沃茨之遗/_build"
python3 check_mod.py ~/Downloads/某个mod.rar        # 压缩包直接喂进去，自动解开
python3 check_mod.py ~/Downloads/某mod文件夹/
python3 check_mod.py ~/Downloads/*.zip
```

它读文件头就能给出「类型 / 风险 / 结论」，**不用启动游戏**。判定依据：

| 类型 | 风险 | 说明 |
|---|---|---|
| `LUA` | **不可用** | 形态是 `Scripts/main.lua` + `enabled.txt`。要 UE4SS 才跑得起来，而主 exe 里搜 `main.lua` / `enabled.txt` / `ue4ss` **全是 0 命中**——游戏本体根本没有 Lua 加载器，官方 mod 系统只认 `*.pak`（exe 里是 `EModsDirectoryMode::CFCore / Flat / None`） |
| `HEADS` | 看日期 | 头部网格替换。**2025-12-03 之前上传的必崩**（Tifa 826 / Draco / Emma 全是）；之后上传的是当前版本做的，可试 |
| `HAIR` | 看日期 | 同上 |
| `CLOTHING` | 低 | 服装类，不碰头部骨骼，实测可装（Champions Leggings） |
| `DATA` | 中 | 替换 `PhoenixShipData.sqlite`，**同时只能存在一个**（UE 整份覆盖，不合并） |
| `UI` / `SCRIPT` / `CONFIG` | 低 | 准星、蓝图、ini，跨版本安全 |

> **日期怎么来的**：脚本从 Nexus 下载文件名里取——`…-2399-1-0-1766549757.zip` 结尾那 10 位是
> epoch，`… 2595 1.0.2 2026-10-27T21-41Z.zip` 中间那段是 ISO 日期。取不到就退回文件修改时间。

还会额外报三种「装了等于没装」的情况：

- **挂载点不对**：写成 `MyProject/`、`Hermione_Wand/` 这类 → 游戏永远读不到
  （实例：哈利波特法杖）
- **legacy pak 的 Offset 写成 0**：数据实际在 53 字节后 → 读到的是文件头
  （实例：负重999、alohomora、UnlockAllSpells、Free_Gear_Upgrade）
- **没有索引的坏包**：`zzz_UnlockGearLimit_P.pak` 就是，8835292 字节但尾部全 0

**它不能判什么**：不能 100% 预测不崩（资源结构变化读不出来）。但它能筛掉
**头部/发型类**和**坏包**——这两类正是之前所有闪退的来源。

### 12.6 数据库类 mod 为什么「装了没反应」（2026-10-31 定位）

所有 8.8 MB 的 pak 都在替换**同一个文件** `Phoenix/Content/SQLiteDB/PhoenixShipData.sqlite`。
UE 对同路径资源是**整份覆盖、不合并**，所以同时装多个只有**字母序最后**的那个生效。

当时的现场（7 个都在，按挂载顺序）：

```
1. Free_Gear_Upgrade.pak            未压缩 ← Offset 坏
2. InfiniteCasting.pak              压缩   ← 格式正确
3. UnlockAllSpells.pak              未压缩 ← Offset 坏
4. alohomora_unlocked_p.pak         未压缩 ← Offset 坏
5. z_RORUpgradoV3_P.pak             未压缩 ← Offset 坏
6. zz_AcceleratedAlchemy_0CD_P.pak  压缩   ← 格式正确
7. zz_Broomunlocktest_P.pak         未压缩 ← Offset 坏   ← 它赢了
```

**赢的那个恰好是坏包**：`Offset` 写成 0，数据实际在 53 字节之后。按游戏的读法
（从 Offset 读 8835072 字节）打开，SQLite 直接报 `file is not a database`。
读失败 → 游戏退回原版数据库 → **所有数据库 mod 一起失效**，表现就是「技能无冷却装了没用」。

**判据（离线就能查，不用启动游戏）**：

```sh
python3 - <<'PY'
import sys, sqlite3
sys.path.insert(0, "/Volumes/SSD/Game/游戏构建/霍格沃茨之遗/_build")
from pakfull import read_pak
p = "<某个 pak>"
pk = read_pak(p); e = pk['entries'][0]
open("/tmp/_t.sqlite","wb").write(pk['data'][e['offset']:e['offset']+e['size']])
print(sqlite3.connect("/tmp/_t.sqlite").execute("PRAGMA integrity_check").fetchone())
PY
```

**修法**：只留**一个**数据库 pak，而且必须是格式正确的（压缩格式，块坐标是绝对偏移）。
实测 `InfiniteCasting.pak` 就是好的——解压出来 529 张表、`integrity=ok`、
162 个法术里 **72 个 `CooldownTime` 被改成 0**（Accio / Confringo / AvadaKedavra / Crucio / Depulso …）。

```sh
# 只留技能无冷却，其余数据库 mod 全部移出 ~mods
mkdir -p "$GAME/Paks_mods_disabled/_sqlite_other"
mv "$MODS"/{Free_Gear_Upgrade.pak,UnlockAllSpells.pak,alohomora_unlocked_p.pak,\
z_RORUpgradoV3_P.pak,zz_AcceleratedAlchemy_0CD_P.pak,zz_Broomunlocktest_P.pak} \
   "$GAME/Paks_mods_disabled/_sqlite_other/"
```

> **想换别的效果**：一次只留一个，把它改名成 `zzzz_<名字>.pak` 保证它排序最后。
> 想同时要多个 → 只能合并数据库，但**手动合并这条路试过两次都崩**（见下），别再走。
>
> **合并为什么失败**：用「多数投票」把 20 个 mod 的数据库合并（排除跨版本的
> `z_RORUpgradoV3_P`），`PRAGMA integrity_check` 通过、关键值抽查也对，
> 但装上去一进文字界面就闪退。这些库不是「原版 + 改几行」的干净差异，投票合出来的库游戏不接受。
