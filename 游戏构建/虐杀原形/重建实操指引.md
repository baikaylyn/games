# 虐杀原形 · 构建文档（重建实操指引）

> **这份只讲「怎么把 App 造出来 / 改完怎么重编 / 造完怎么验证」。**
> 日常怎么用、面板每一项落哪里、完整坑位清单，见旁边的 `说明.md`（App 旁边那份）。
>
> 三处副本，内容完全一致：
> - **合集**：`总重建指引.md` 第 2 部分（`bash _生成总文档.sh` 自动生成）
> - **固态单独**：`/Volumes/SSD/Game/游戏构建/虐杀原形/重建实操指引.md`
> - **本机单独**：`~/Games/游戏构建/虐杀原形-重建实操指引.md`
>
> 权威源是固态那份；改完跑 `bash _同步到本机.sh` 再跑 `bash _生成总文档.sh`。

## 第 0 节 · 构建流程总览

全量构建 = **4 步 + 3 个必做改动**，约 20 分钟（不含解压 8 GB 素材）。

| 步骤 | 做什么 | `build_prototype.py` 里的函数 | 耗时 |
|---|---|---|---|
| 1 | 内嵌 Wine 运行时（`cp -cR` APFS 克隆） | `step_wine()` | 10~30 秒 |
| 2 | 内嵌游戏本体（`cp -cR`，8 GB） | `step_game()` | 10~30 秒 |
| 3 | 编译启动器（clang + strip） | `step_launcher()` | 3 秒 |
| 4a | **构建期改动：禁用 MoltenVK** | `step_tweaks()` | 1 秒 |
| 4b | 写 `Info.plist` / `PkgInfo`、清 `cstemp`、清 xattr | `step_app()` | 2 秒 |
| 4c | **ad-hoc 签名（固定 identifier 要求）** | `step_app()` | 5~20 秒 |
| 后置 | **wow64cpu 补丁**（换过 Wine 才需要） | `wow64cpu_rosetta_patch.py` | 1 分钟 |

> 第 4a / 4c 是 2026-10-30 补进来的，都是「不做就会踩坑」的硬要求，见第 4 节。

## 第 2 节 · 从零全量构建

### 2.1 准备

- 空闲空间 **≥ 20 GB**（8 GB 素材 + 8.6 GB App + prefix）
- **路径必须纯英文**。中文路径会被 Wine 转成 `????`，引擎初始化失败（白窗口 → 静默退出）
- **别在外置 USB 盘上构建**：慢 3–5 倍，中途拔盘即废。先拷到本机再编

### 2.2 解素材

```sh
mkdir -p ~/Games/Prototype/_src
cd /tmp && bsdtar -xf "/Volumes/SSD/Game/Prototype.rar" Prototype
mv Prototype ~/Games/Prototype/_src/Game

mv wine-staging-11.18-osx64 ~/Games/Prototype/_src/Wine
~/Games/Prototype/_src/Wine/bin/wine --version     # 必须打印 wine-11.18 (Staging)
```

### 2.3 跑构建

```sh
cd "/Volumes/SSD/Game/游戏构建/虐杀原形/_build"
python3 build_prototype.py
```

预期输出：

```
[1/4] 运行时
  复制 Wine → …/Resources/Wine
[2/4] 游戏数据
  克隆游戏数据 7.9 GB → …/Resources/Game
[3/4] 启动器
  编译 launcher.m → …/Contents/MacOS/Prototype
[4/4] 运行时改动 + 组装与签名
  已禁用 MoltenVK（改名为 libMoltenVK.dylib.disabled）
  写 Info.plist
  ad-hoc 签名（16 GB 级别的包不加 --deep，只签本体，几秒完成）
完成：…/Prototype.app
```

### 2.4 打 wow64cpu 补丁（**必做**）

新建的 App 里 `wow64cpu.dll` 是原版，启动会概率性崩在 Rosetta 的 32/64 位切换上：

```sh
python3 "/Volumes/SSD/Game/游戏构建/虐杀原形/_build/wow64cpu_rosetta_patch.py"
python3 "/Volumes/SSD/Game/游戏构建/虐杀原形/_build/wow64cpu_rosetta_patch.py" --check
```

补丁会改 bundle 里的文件 → **必须重签**（带固定要求，见 4.2）：

```sh
APP="$HOME/Games/Prototype/Prototype.app"
codesign --force --sign - \
  --requirements '=designated => identifier "org.macnativegames.prototype"' "$APP"
```

### 2.5 首次运行

```sh
touch "$HOME/Library/Application Support/MacNativeGames/PROTOTYPE/autoplay"   # 可选：跳过面板
open -a "$HOME/Games/Prototype/Prototype.app"
```

依次会：弹「访问文稿文件夹」→ 点**允许** → 首次 `wineboot -u` 建 prefix（约 1 分钟，无进度条）→ 出画面。

## 第 3 节 · 只重编启动器（99% 的情况）

改完 `launcher.m` 用这个，几秒完成，**不需要素材**：

```sh
cd "/Volumes/SSD/Game/游戏构建/虐杀原形/_build"
python3 build_prototype.py --launcher
```

它只跑第 3、4 步（编译 + 运行时改动 + 签名），不碰 Wine 和游戏数据。
`--launcher` 也会走 `step_tweaks()`（幂等，已禁用就跳过）和 `step_app()`（重新签名）。

> **重编前先退出启动器**（Cmd+Q）。运行中的实例占着 `Contents/MacOS/Prototype`，
> 覆盖会失败或留下半个二进制。

## 第 4 节 · 构建期必须做的三个改动

这三条不是"优化"，是不做就会出问题。

### 4.1 禁用 MoltenVK（`step_tweaks()`）

`wined3d` 初始化时会**无条件建一个 Vulkan 实例**做能力探测——日志里那大段
`[mvk-info] MoltenVK version 1.4.0 ... Created VkInstance` 就是它。
这个初始化在 Rosetta 下会概率性把进程带崩，唯一痕迹：

```
00f8:err:seh:send_debug_event Exception c0000005 in system thread at 0x7ff81136a622
```

地址**不在** `0xBF2xxxx` 区间，所以 wow64cpu 补丁治不了它。
而 `WINEDLLOVERRIDES` 里的 `winevulkan=d` **也挡不住**——那段探测是 unix 侧直接
`dlopen libMoltenVK.dylib`，绕过了 DLL 覆盖。

**做法**：把 `Contents/Resources/Wine/lib/libMoltenVK.dylib` 改名成 `.disabled`。
D3D9 走 OpenGL，用不到 Vulkan，无副作用。

**效果**：开启时 4 次启动挂 1~2 次；禁用后 **4/4 全成功**（片头 386~498 fps），
双击启动器路径再测 3/3 全部第 1 次就起来。

### 4.2 签名要求固定成 `identifier`（`step_app()`）

```sh
codesign --force --sign - \
  --requirements '=designated => identifier "org.macnativegames.prototype"' "$APP"
```

**为什么**：ad-hoc 签名默认的 designated requirement 是 `cdhash H"…"`，
而 cdhash 每次重建都会变 → 所有 TCC 授权（辅助功能、文稿目录）全部失效，
用户每次重建都得重新点一遍开关。固定成 identifier 之后重建不再影响已有授权。

这是从鬼泣4 那边搬过来的结论（那边为这个坑反复返工过）。**构建脚本里已经写死，别删。**

### 4.3 清 `cstemp` + 清 xattr（`step_app()` 里）

```sh
find "$APP" -name "*.cstemp" -delete
xattr -cr "$APP"
```

上一次签名被打断会留下 `Contents/MacOS/Prototype.cstemp`，它会被写进资源封印，
之后 `codesign -v` 永远报 `a sealed resource is missing or invalid`（踩过，排查很久）。
清 xattr 是为了避免 `com.apple.provenance` 之类带进新签名。

## 第 5 节 · wow64cpu 补丁（换过 Wine 就要重打）

| 检查 | 命令 | 期望 |
|---|---|---|
| 补丁在不在 | `python3 _build/wow64cpu_rosetta_patch.py --check` | 「四个站点全部匹配」或「代码洞不干净」（后者=补丁已在里面） |
| 启动器怎么判 | `grep wow64cpu logs/launcher.log \| tail -1` | `wow64cpu 补丁：已打` |

**换 Wine 版本补丁会消失**（Wine 官方把这类问题判成 NOTOURBUG，不会修）。
补丁改的是 bundle 内文件，所以打完必须重签（见 4.2）。

## 第 6 节 · 构建后的验证

逐条打勾，别只看"能开"：

```sh
APP="$HOME/Games/Prototype/Prototype.app"
D="$HOME/Library/Application Support/MacNativeGames/PROTOTYPE"

codesign -v "$APP" && echo "签名 OK"
codesign -d -r- "$APP" 2>&1 | tail -1        # 必须是 designated => identifier "..."
"$APP/Contents/Resources/Wine/bin/wine" --version
ls "$APP/Contents/Resources/Wine/lib/" | grep MoltenVK   # 只能有 .disabled / .orig
python3 "/Volumes/SSD/Game/游戏构建/虐杀原形/_build/wow64cpu_rosetta_patch.py" --check
```

- [ ] `codesign -v` 通过，且要求是 `designated => identifier "org.macnativegames.prototype"`
- [ ] Wine 打印 `wine-11.18 (Staging)`
- [ ] `libMoltenVK.dylib` 不存在（只剩 `.disabled` / `.orig`）
- [ ] wow64cpu 补丁在位
- [ ] 双击出面板，无报错弹窗
- [ ] 点「开始游戏」→ `pgrep -f prototypef.exe` 有进程
- [ ] 窗口是**居中**的（`logs/launcher.log` 有 `窗口已居中`；没有就是辅助功能没授权）
- [ ] `logs/launcher.log` 有 `MoltenVK：已禁用`、`显示模式：窗口（…）`
- [ ] 画面能看到 `[PROTOTYPE] PRESS ENTER`
- [ ] 启动稳定性：`bash _build/soak.sh 4` 结果 **4/4**
- [ ] 存档能读出来（进游戏 → CONTINUE）

**启动稳定性压测**（不靠眼睛，靠日志判「出帧」）：

```sh
cd "/Volumes/SSD/Game/游戏构建/虐杀原形/_build"
TAG="构建后验收" bash soak.sh 4
```

正常输出是 4 行「成功（出帧，末帧 380~500 fps）」。低于 4/4 先查 MoltenVK 有没有真的禁掉。

## 第 7 节 · 构建相关坑位（按严重程度）

1. **忘了禁 MoltenVK** → 启动 3 秒左右直接退出，日志只有
   `Exception c0000005 in system thread`。`launcher.log` 会写 `MoltenVK：未禁用`，一眼可查。
2. **签名没带 `--requirements`** → `codesign -d -r-` 显示 `cdhash H"…"`。
   后果：重建后辅助功能授权失效 → 窗口不再居中（停在左上角）；文稿目录授权也会重新弹。
3. **`cstemp` 残留** → `codesign -v` 报 `a sealed resource is missing or invalid`，
   而且重签也修不好（因为 `.cstemp` 会被重新封印进资源清单）。必须先 `find -delete` 再签。
4. **编译输出文件名不是 `Prototype`** → ad-hoc 签名的 identifier 由文件名派生，
   与 `Info.plist` 的 `CFBundleExecutable` 不一致时会被判签名无效（`SIGKILL`）。
5. **在 bundle 内直接签名 8.6 GB 的包并加 `--deep`** → 扫全树，几十秒到几分钟。
   现在脚本**不加 `--deep`**，只签本体；Wine 树放 `Resources` 当普通数据。
6. **构建时启动器还在跑** → 覆盖 `Contents/MacOS/Prototype` 失败或留下半截文件。
   先 `pkill -9 -f 'MacOS/Prototype'`。
7. **素材路径带中文** → Wine 把路径转成 `????`，prefix 建不起来，白窗口后静默退出。
8. **换了 Wine 版本忘了重打 wow64cpu 补丁** → 启动崩在 `page fault … at address 7BF21239`
   （或 `7BF21135`）。`launcher.log` 会写 `wow64cpu 补丁：未打`。
9. **改 `launcher.m` 后忘了重编就以为改生效了** → 面板看起来变了但行为没变。
   认准 `python3 build_prototype.py --launcher` 跑过、且 `codesign -v` 通过。
10. **顺手把 `--requirements` 那段删掉"简化一下"** → 回到坑 2。这行是刻意的。

## 第 8 节 · 构建产物 vs 运行期产物

分清楚才不会"重建一次丢一次"。

| 属于 | 位置 | 重建会怎样 |
|---|---|---|
| 构建产物 | `Prototype.app/Contents/Resources/{Wine,Game}` | 重新克隆（内容不变） |
| 构建产物 | `Prototype.app/Contents/MacOS/Prototype` | 重新编译 |
| 构建产物 | `Prototype.app/Contents/Info.plist` | 重新写 |
| 构建产物 | `Prototype.app/Contents/Resources/Wine/lib/libMoltenVK.dylib.disabled` | 由 `step_tweaks()` 生成 |
| **运行期** | `…/PROTOTYPE/prefix`（约 393 MB） | **不碰**，重置环境才会删 |
| **运行期** | `…/PROTOTYPE/launcher-settings.json` | **不碰** |
| **运行期** | `…/PROTOTYPE/logs/{launcher,prototype}.log` | **不碰** |
| **运行期** | `…/PROTOTYPE/saves-backup/` | **不碰** |
| **不可再生** | `~/Documents/Prototype/{profile.bin, slot-A…F.bin}` | **绝对不碰**（存档） |

> 重建 App 前建议先点面板「备份存档」（拷到 `saves-backup/<时间戳>/`）。
> 重置 prefix 不影响存档（两个不同目录），但**换机器**要手动带走 `~/Documents/Prototype`。

## 第 9 节 · 回滚与重装

| 情况 | 做法 |
|---|---|
| 只想撤销 MoltenVK 禁用 | `mv libMoltenVK.dylib.disabled libMoltenVK.dylib` 后重签（会回到启动概率崩） |
| 启动器改坏了 | `git` 没有的话：从 `_同步到本机.sh` 同步下来的 `_build/launcher.m` 重新 `--launcher` |
| App 整个坏了 | 重跑全量构建（第 2 节），prefix 和存档都还在 |
| prefix 半损（`wineboot` 反复失败） | 面板「重置环境」（先杀会话再删 prefix），约 1 分钟 |
| 存档要还原 | 把 `saves-backup/<时间戳>/*.bin` 拷回 `~/Documents/Prototype/` |
