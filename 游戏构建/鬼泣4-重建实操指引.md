# 鬼泣4 特别版 · 重建实操指引

> **一句话结论**：这个包**能跑、画面完全正确**，瓶颈是 32 位程序套 wined3d 的翻译开销。
> 默认已调到「最低画质 + 1024x576 + 显存 4096MB」，实测 **48~53 fps**，可玩。
> 想再快就换 960x540（47~55 fps，收益只有 4%，不划算）。

---

## 第 0 节 · 先判断（大多数情况不用重建）

| 症状 | 怎么办 | 耗时 |
|---|---|---|
| App 不见了 | 从固态 `DMC4/` 拷回来（27 GB），别重装 | 10 分钟 |
| 双击只出启动器面板、点开始没反应 | 关掉面板，重新双击；或 `pkill -9 -f wineserver` 后再双击 | 30 秒 |
| 画面正常但**巨卡**（15~20 fps） | 注册表 `VideoMemorySize` 没写 → 见第 4 节，一行修好 | 2 分钟 |
| 人物变成**全黑剪影** | 有人把 `WINE_D3D_CONFIG=renderer=gl` 加进去了，删掉 | 1 分钟 |
| 弹 `D3D10 create failed: msg_handler_UnInitializePackage` | 手工 `wine` 命令启动才会出；**必须用启动器启动** | — |
| 菜单里回车/ESC 没反应 | 输入法在吃按键，切英文（`Ctrl+Space` 或第 8 节的工具） | 5 秒 |
| 想量帧率 | 把 `METAL_HUD` 改回 `1`（见第 2 节），右上角就有数字 | 1 分钟 |
| 改了 `config.ini` 又变回去 | 正常，游戏退出会重写；要改就退出游戏后改 | — |

## 第 1 节 · 这个包是什么

| 项 | 值 |
|---|---|
| App | `/Volumes/SSD/Game/DMC4/Devil May Cry 4.app`（27 GB） |
| 可执行 | `prefix/drive_c/Program Files (x86)/Devil May Cry 4 Special Edition/DevilMayCry4SpecialEdition.exe` |
| 位宽 | **PE32 / i386（32 位）**，`machine=0x014c`，15.8 MB |
| 图形接口 | **只有 D3D10**（直接导入 `d3d10.dll`），`nativeDX10/` 资源 25 GB，**没有 DX9 回退路径** |
| Wine | `KegworksCX 24.0.7 (revision 0)` = Wine 9.0，x86_64 薄二进制 + Rosetta 2 |
| 渲染链路 | `d3d10.dll` → wined3d → Vulkan → **MoltenVK**（`MOLTENVKCX=1`） |
| 启动器 | 原厂 Kegworks 面板，`open -a` 启动正常（直接跑 `Contents/MacOS/Kegworks` 会报 `FileUtilsError error 1`） |

**为什么只能走 D3D10**：游戏本体只带 `nativeDX10`，D3D9 路径被删了。
所以「改用 DXVK 的 d3d9」这条路不存在。

## 第 2 节 · 当前最佳配置（定版）

### 2.1 `Contents/Info.plist`（决定后端）

| 键 | 值 | 说明 |
|---|---|---|
| `D3DMETAL` | `1` | 原厂默认 |
| `DXMT` | `0` | 关 —— DXMT 的 32 位 DLL 在这个 Wine 上装不进去（第 7 节） |
| `DXVK` | `0` | 同上 |
| `D9VK` | `0` | 游戏没有 DX9 路径，开了也没用 |
| `MOLTENVKCX` | `1` | **必须有**：wined3d 走 Vulkan 就靠它接到 MoltenVK |
| **`METAL_HUD`** | **`0`**（交付值） | 排障时改 `1`，右上角出 FPS/Pre/GPU/Mem |
| **`FASTMATH`** | **`1`** | MoltenVK 快速数学（`MVK_CONFIG_FAST_MATH_ENABLED`），降低着色器 ALU 开销；已实测不破坏画面 |
| **`CLI Custom Commands`** | `export LANG=zh_CN.UTF-8; cp -f "<_build>/config.ini" "<prefix>/…/config.ini"` | **启动前自动写回定版画质**，双击 app 也能生效（解决 `TextureDetail` 被回写 HIGHEST 的老问题） |
| `WINEDEBUG` | `-plugplay,+loaddll` | 原厂默认，别改成 `-all` |

> ⛔ **绝对不要设 `WINE_D3D_CONFIG=renderer=gl`**。
> 那条会把 wined3d 赶到 OpenGL：帧率掉到 8 fps，而且**所有人物变全黑剪影**。

改 HUD 开关：

```sh
A="/Volumes/SSD/Game/DMC4/Devil May Cry 4.app"
plutil -replace METAL_HUD -string 1 "$A/Contents/Info.plist"   # 开
plutil -replace METAL_HUD -string 0 "$A/Contents/Info.plist"   # 关
```

### 2.2 `config.ini`（最低画质定版）

路径：`prefix/drive_c/users/Kegworks/AppData/Local/CAPCOM/DEVILMAYCRY4SPECIALEDITION/config.ini`

```ini
[GRAPHICS]
HDR=DEFAULT
AntiAlias=NONE
AltAntiAlias=NONE
DeferredLightingLight=MONOCHROME_SPECULAR
DeferredLightingHDR=INTEGER_LOG
SLI=OFF
GodRay=OFF
Stereo=OFF
EffectVolume=LOW
TextureResolution=0
Quality=0
FrameRate=2
TextureDetail=LOW
TextureMipLimite=2
[DISPLAY]
Resolution=1024x576
Aspect=DEFAULT
RefreshRate=60.00Hz
FullScreen=OFF
VSYNC=OFF
[CPU]
JobThread=4
RenderingThread=ON
```

**合法枚举值全表**（从 exe 里 `strings -a -t d` 挖出来的，写错会被静默丢弃并回写默认）：

| 配置项 | 合法值（exe 里的完整形式 → 写入 ini 时**去掉前缀**） | 定版 |
|---|---|---|
| `DeferredLightingLight` | `DL_LIGHT_MONOCHROME_SPECULAR` / `DL_LIGHT_APPROXIMATE_SPECULAR` / `DL_LIGHT_SEPARATE_SPECULAR` | `MONOCHROME_SPECULAR`（最便宜） |
| `DeferredLightingHDR` | `DL_HDR_INTEGER` / `DL_HDR_FLOAT` / `DL_HDR_FLOAT_PRECISION` / `DL_HDR_INTEGER_LOG` | `INTEGER_LOG` |
| `TextureDetail` | `TEXDETAIL_LOWEST` / `TEXDETAIL_LOW` / `TEXDETAIL_MEDIUM` / `TEXDETAIL_HIGH` / `TEXDETAIL_HIGHEST` | `LOW` |
| `HDR` | `HDR_DEFAULT` / `HDR_FLOAT` | `DEFAULT` |

> **写法要点**：ini 里的值是**去掉前缀**的。exe 枚举叫 `DL_LIGHT_MONOCHROME_SPECULAR`，
> ini 里就写 `MONOCHROME_SPECULAR`。此前试的 `UNLIT`、`TextureDetail=0` 被丢弃，
> 就是因为它们压根不在枚举里。
>
> ⚠️ **`TextureDetail` 会被游戏回写成 `HIGHEST`**（实测每次退出 config 都被改回去）。
> 所以最低画质**必须在每次启动前重新写入**，否则从来没真正生效过。
> `_鼠标操作.sh` 已内置这一步（启动前 `cp` 一次定版 config.ini）。
> 详见第 6 节坑位 25。

其余要点：

- `Quality=0` 是最低档；`TextureResolution=0`、`EffectVolume=LOW` 是单项最低。
- `TextureMipLimite` 写 `0` 会被游戏**回写成 2**（说明 0 不合法）。别再试。
- 分辨率**可以写任意值**（`960x540`、`1024x576` 都实测生效，窗口会跟着变）。

### 2.3 注册表（**这是帧率翻倍的关键**）

`prefix/user.reg` → `[Software\\Wine\\Direct3D]`：

```
"VideoMemorySize"="4096"
"csmt"="3"
"OffscreenRenderingMode"="fbo"
"renderer"="vulkan"
```

原厂这一节是**空的**，wined3d 用自动探测的显存值（偏小），导致纹理每帧被反复换出。
改成 `4096` 后同一场景帧率 **19.9 → 40 fps**，`Mem` 从 2.16 GB 降到 1.5~1.7 GB。

改注册表**必须先退出游戏和 wineserver**，否则会被覆盖回写：

```sh
pkill -9 -f "Devil May Cry 4.app"; pkill -9 -f DevilMayCry4; pkill -9 -f wineserver; sleep 3
# 然后才能编辑 user.reg
```

## 第 3 节 · 从零重建

1. 把 `DMC4/Devil May Cry 4.app` 整个拷到本机或固态同名位置（用 `ditto`，保留符号链接）。
2. 检查 `Contents/SharedSupport/wine/lib/wine/i386-windows/` 下这 5 个 DLL 是**原厂大小**：

   | 文件 | 字节数 |
   |---|---|
   | `d3d10.dll` | 237582 |
   | `d3d10_1.dll` | 49166 |
   | `d3d10core.dll` | 45070 |
   | `d3d11.dll` | 364558 |
   | `dxgi.dll` | 208910 |

   对不上就从原始挂载卷拷回来。**别删 `d3d10.dll`** —— 游戏直接导入它，删了就是 `d3d10.dll not found`。

3. 照 2.1 核对 `Info.plist`（重点是 `MOLTENVKCX=1`、`METAL_HUD=0`、不设 `WINE_D3D_CONFIG`）。
4. 照 2.2 写 `config.ini`。
5. 照 2.3 写注册表（**这才是性能的关键**）。
6. `open -a "/Volumes/SSD/Game/DMC4/Devil May Cry 4.app"`，等 60~80 秒进标题画面。

一键执行 4~5 步：`bash "/Volumes/SSD/Game/游戏构建/鬼泣4/_build/_应用优化.sh"`

## 第 4 节 · 性能优化实操（怎么从 15 fps 救到 50 fps）

按收益从大到小排，前两条就能救回来：

| # | 动作 | 收益 | 代价 |
|---|---|---|---|
| 1 | 注册表 `VideoMemorySize=4096` | **+100%**（19.9 → 40 fps） | 无 |
| 2 | `Resolution=1024x576` | **+25%**（40 → 50 fps） | 画面变软 |
| 3 | `Quality=0` + 三个单项最低 + `GodRay=OFF` | +10~20% | 特效变少 |
| 4 | `Resolution=960x540` | 只再 +4% | 更糊，**不建议** |
| 5 | `JobThread=9 → 4` | 减少线程争抢，波动变小 | 无 |

**没用的动作**（别浪费时间）：

- ❌ 关垂直同步（本来就 `VSYNC=OFF`）
- ❌ 继续降分辨率到 540p 以下 —— 低于 540p 后 GPU 已经不是瓶颈
- ❌ 换 `renderer=gl` —— 画面直接废掉
- ❌ 加 DXVK / DXMT —— 32 位 DLL 根本装载不进去（第 7 节）
- ❌ 改 `DeferredLightingLight` / `TextureMipLimite` —— 非法值会被静默丢弃

**为什么低分辨率收益越来越小**：GPU 时间从 23.6 ms 降到 ~11 ms 之后，
每帧剩下的 ~9 ms 是 wined3d 的绘制调用翻译 + Rosetta 翻译，跟像素数无关。
所以 **1024x576 是甜点**，再降只是变糊。

## 第 5 节 · 实测数据（2026-10-29）

Metal HUD 读法：**`FPS:` 那行就是帧率，`Pre:` 是每帧毫秒，两者互为倒数**（`1/0.0210 = 47.6`）。
`GPU:` 是 GPU 毫秒。别把 `FPS:` 当成毫秒读，会得到完全相反的结论。

**怎么量（不用肉眼看 HUD）**：`_build/` 里有 `ocr.m` + `hudread.sh`，
用 macOS Vision 把 HUD 数字直接解析出来：

```sh
cd "/Volumes/SSD/Game/游戏构建/鬼泣4/_build"
clang -O2 -fobjc-arc -o ocr ocr.m -framework Vision -framework AppKit -framework Foundation
./hudread.sh <窗口ID> 5 2        # 抓 5 张、每张间隔 2s，自动打出 FPS/GPU/Mem
```

前提 `METAL_HUD=1`。窗口 ID 用 `./winid | grep -i CRY` 取。
> ⚠️ **A/B 对比必须用同一机位**。换场景时的帧率差异会完全盖过画质设置的差异，
> 本次就因此差点得出「最低画质反而更卡」的错误结论（两边其实不在同一场景）。
> 要严格对比就进游戏内置 **Benchmark**（固定镜头路径，可重复）。

| 场景 | 分辨率 | 画质 | FPS | GPU ms | 备注 |
|---|---|---|---|---|---|
| 剧院广场 · 强光固定机位 · 优化前 | 1280x720 | 最低 | **16~20** | 23~44 | 注册表没写显存 |
| 剧院广场 · 强光固定机位 · 定版 | 1280x720 | 最低+单色镜面 | **16.5** | 39.7 | 加了注册表也没救回来 |
| 剧院广场 · 强光固定机位 · 定版 | 800x450 | 最低+单色镜面 | **19.5** | 37.5 | **降分辨率几乎无效** |
| 室内走廊 / 楼梯 | 1280x720 | 最低 | 23~27 | 27~32 | 比广场好些 |
| 看天空的空旷视角 | 1024x576 | 最低 | 48~53 | ~11 | 便宜视角，不能代表战斗 |
| 预渲染过场视频 | 1280x720 | 默认 | 118~122 | 2.4 | 视频解码，与 3D 性能无关 |

> ⚠️ **表里"看天空 48~53 fps"不能当作可玩性依据**。早期我是在人物往前走、镜头对着天空的
> 便宜视角测的，那个数字严重乐观。**真实战斗/强光场景是 16~20 fps。**

- 内存占用：优化前 2.16 GB → 优化后 **1.47~1.70 GB**
- `DeferredLightingLight` 实测有 **3 个合法值**（从 exe 里挖出来的枚举 `DL_LIGHT_*`）：
  `SEPARATE_SPECULAR` / `APPROXIMATE_SPECULAR` / **`MONOCHROME_SPECULAR`**。
  定版用最便宜的 `MONOCHROME_SPECULAR`，游戏**接受并保留**（不会像 `UNLIT` 那样被丢弃）。
- **瓶颈结论（修正版）**：
  - 强光场景里 GPU 独占 37~40 ms，而把分辨率从 720p 降到 450p 只快了 18%
    → **大头是阴影/延迟光照这类「与屏幕像素无关的固定开销」**，降分辨率救不回来。
  - 轻场景（室内、空旷）GPU 掉到 11~27 ms，此时才轮到分辨率说话。
  - 所以 **1024x576 是折中定版**；想再快一点可以用 800x450，但只多 18%，画面明显变糊。
  - 想真正解决强光场景，只能绕开 wined3d 的绘制调用翻译层；而 DXVK/DXMT 装不进来（第 7 节），
    **这套环境的天花板就在这里**。

**鼠标化操控实测验证（2026-10-29，v4 重映射器）**

判据：截图做像素差分，**无操作噪声底仅 0.84**，任何动作都远超它。

## 第 6 节 · 坑位清单

1. **只有 DX10，没有 DX9** —— DXVK/d9vk 路线直接不存在。
2. **`d3d10.dll` 不能删** —— 游戏直接导入，删了报 `d3d10.dll not found`。
3. **`wineboot -u` 会覆盖 `syswow64` 里的原生 DLL**（实测 1809141 → 208910 字节）。别跑。
4. **手工 `wine` 启动必弹 `D3D10 create failed`** —— 启动器会做后端部署和预处理，
   手工命令不会。**一律用 `open -a` 启动。**
5. **`open -a` 不要在游戏启动后重复调用** —— 它会激活 Kegworks 启动器本体而不是 wine 窗口，
   游戏丢掉 key window 后**再也拿不回焦点**（键盘全失效）。要抢焦点就点窗口标题栏。
6. **窗口坐标换算**：`winid` 报的是真实点坐标（如 `1024x604 @ 35,33`，含 28 px 标题栏）。
   截图预览常被缩放显示，**别拿预览图上的坐标去点击**，差 1.78 倍。
7. **`renderer=gl` 会在 8 fps 下把人物渲染成全黑剪影** —— 一定要走 Vulkan/MoltenVK。
8. **`config.ini` 每次退出都会被游戏重写** —— 非法值会被静默改回默认。改之前先退游戏。
9. **`TextureMipLimite=0` 不合法**，会被回写成 `2`。
10. **配置项的值必须是 exe 枚举里的合法值**，写 `UNLIT` 之类会被静默丢弃并回写默认。
    完整枚举表见 2.2 节。**写入 ini 时要去掉前缀**（`DL_LIGHT_*` / `DL_HDR_*` / `TEXDETAIL_*`）。
11. **键盘被输入法吃掉**：中文输入法下 Enter/ESC 会被 IME 拦（`macdrv_ImeProcessKey`），
    表现为「按了没反应」或「按任何键都变成下移」。切成 ABC 英文键盘就好，见第 8 节。
12. **`METAL_HUD=1` 会一直显示右上角数字**，交付前记得改回 `0`。
13. **32 位 WoW64 路径**：这是它比港诡实录（64 位）慢得多的根本原因，不是配置问题。
14. **强光场景降分辨率基本无效**：GPU 37~40 ms 是阴影/延迟光照的固定开销，720p→450p 只快 18%。
    别指望靠降分辨率救强光广场。详细数据见第 5 节。
15. **`DeferredLightingLight` 合法值只有三个**（从 exe 枚举 `DL_LIGHT_*` 挖的）：
    `SEPARATE_SPECULAR` / `APPROXIMATE_SPECULAR` / `MONOCHROME_SPECULAR`。定版用 `MONOCHROME_SPECULAR`。
16. **合成按键绝不能写 `kCGEventSourceUserData`**：赋非零值会被系统当无效事件丢弃（第 9.4 节）。
17. **点按时长必须 ≥ 1 帧**（≥60 ms，稳妥用 120~160 ms）。游戏 16~25 fps，短按会被整帧漏掉。
18. **不要在事件拦截回调里 `usleep`**：自己发的事件会被挤到一起送达，等于没按。
19. **窗口列表里可能混进 28×36 的辅助窗口**：按窗口号抓图时要挑标题是
    `DEVIL MAY CRY 4 Special Edition` 的那个，`head -1` 容易抓错。
20. **鼠标视角判定不能用单次事件 delta**：慢移时每次 delta 只有 1，永远达不到死区阈值，
    表现是"视角完全不跟手"。要**累积位移**，停手后衰减释放方向键。
21. **前台判断必须缓存**：鼠标每秒上百条移动事件，每次全量遍历窗口列表会吃满 CPU。
    定版 200 ms 刷新一次。
22. **必须用 `kCGEventSourceUnixProcessID == getpid()` 放行自家合成事件**：
    否则 `Shift→空格` 会被自己的 `空格→K` 二次改写，锁定变成跳跃。
23. **鼠标捕获退出必须还原 `CGAssociateMouseAndMouseCursorPosition(1)`**：
    `atexit` 不覆盖 `SIGTERM`，被 `pkill` 杀掉会漏，光标会一直解耦像坏了一样。
24. **测试工具把鼠标事件位置写成 `(0,0)` 等于瞬移光标到原点**，
    会被误判成"捕获失效"。模拟相对移动要保持位置不变、只写 delta。
25. **`TextureDetail` 每次退出都会被游戏回写成 `HIGHEST`**（实测）。
    只在装机时写一次最低画质**从来没真正生效过**——必须在每次启动前重新写入。
    `_鼠标操作.sh` 已内置这一步。同理 `TextureMipLimite=0` 会被回写成 `2`。
26. **`./swic` 不带参数只是列出输入法清单，不会切换**。必须 `./swic keylayout.ABC`。
    切不掉中文输入法时 Enter/ESC 全被 IME 吃掉，表现为"菜单按不动"，
    会让人误以为游戏卡死或键位失灵（本次就是这么在标题画面卡了很久）。

## 第 7 节 · 为什么不用 DXVK / DXMT（别再试了）

这两个是唯一能让 Metal 直接跑 D3D 的方案，理论上快很多，但**在这个 Wine 上装不进去**。

- 现象：把 DXMT 的 32 位 `dxgi.dll` / DXVK 的 32 位 `d3d11.dll` 放进游戏目录或
  `syswow64`，游戏一律报 `d3d10core.dll not found`（`c0000135`）。
- 根因（读了 `dlls/ntdll/loader.c` 定位）：`open_dll_file()` 里 `NtCreateSection(SEC_IMAGE)`
  **拒绝大映像**。`steam_api.dll`（`SizeOfImage` 405 KB）能映射；
  DXMT `dxgi.dll`（1.37 MB）、DXVK `d3d11.dll`（3.77 MB）全部失败。
- 排除项（全试过，都无效）：ImageBase、FileAlignment、Characteristics、Subsystem、
  TLS 目录、清空导入表、把文件尾部膨胀到 4.5 MB（`SizeOfImage` 不变仍能映射）
  → **是 `SizeOfImage` 本身的硬限制，不是文件大小**。
- 结论：**Kegworks 24.0.7 的 wow64 内核就这么大胃口**，32 位大映像装不进来。
  要上 DXVK/DXMT 只能换 64 位游戏，或者等更新的 Wine 修掉这条限制。

### 9.3 鼠标化操作（`_build/dmc4_input_v4`，系统层重映射）

游戏本身**不支持鼠标转视角**，也**不给任何键位绑定鼠标**（菜单里改不出来）。
所以只能在系统层拦截鼠标事件，翻译成它认识的按键。

**前提：游戏内键位必须是 Capcom 出厂值**，否则重映射器发的键会被曲解。
被改乱了就进 `SYSTEMS` → 右翻到角色页 → 底部 **`DEFAULT`** 一键复原
（复原后是 `MELEE I / GUN J / JUMP K / BRINGER L / TRIGGER N / LOCK-ON 空格 / EXCEED Q`）。

```sh
bash "/Volumes/SSD/Game/游戏构建/鬼泣4/_build/_鼠标操作.sh"            # NERO（开局角色）
bash "/Volumes/SSD/Game/游戏构建/鬼泣4/_build/_鼠标操作.sh" --melee j  # 但丁 / 维吉尔
bash "/Volumes/SSD/Game/游戏构建/鬼泣4/_build/_鼠标操作.sh" --release  # 光标不跟手时还原
```

| 你的操作 | 实际发给游戏 | 说明 |
|---|---|---|
| **鼠标左键** | `I` 近战（`--melee j` 时是 `J`） | |
| **鼠标右键** | `L` 鬼手 / 风格技 | |
| **鼠标中键 / 侧键 / 键盘 `F`** | `J` 枪（`--melee j` 时是 `I`） | 三个入口任选，方便左手右手 |
| **键盘 左/右 `Shift`** | `空格` 锁定（按住） | Shift 只产生 `FlagsChanged`，没有 KeyDown |
| **键盘 `空格`** | `K` 跳跃 + 确认 | 游戏里确认与跳跃本来就是同一个键 |
| **鼠标移动** | `↑↓←→` 转视角 | 光标**锁在游戏框内**，不会滑出去 |
| 长按 `Cmd` | 放行 | 临时去操作别的窗口 |
| `Ctrl+C` | 退出重映射器 | |

**枪械键为什么这么设计**：近战/鬼手已占左右键，枪械放到**中键 + 侧键 + 键盘 `F`**
—— 中键/侧键在右手拇指区，与左右键形成"近战—枪—鬼手"三角；`F` 是左手备用，
战斗中不用离开 `WASD` 就能开枪。滚轮没绑（游戏用不上，留给系统）。

**鼠标捕获的实现**（这是"视角跟随鼠标 + 光标不出框"的关键）：

```c
CGWarpMouseCursorPosition(窗口中心);        // 光标先钉进窗口
CGAssociateMouseAndMouseCursorPosition(0); // 物理鼠标位移与光标解耦
```

解耦之后，物理鼠标的移动**只产生 delta、不推动光标**，所以光标永远不会滑出窗口；
每 10 ms 再钳制一次，任何来源把光标带出框就拉回中央。
长按 `Cmd` 或切到别的窗口时自动解除，退出时用 `--release` / 信号处理还原
（**必须还原**，否则光标会一直解耦，看起来像鼠标坏了）。

### 9.4 写这类重映射器踩到的六个坑（别再犯）

1. **点按必须 ≥ 1 帧**。游戏只有 16~25 fps，一帧 40~60 ms。
   20 ms 的 keyDown/keyUp 会整段落在两帧之间被完全丢弃，表现是"程序说发了，游戏毫无反应"。
   实测：`I` 用 20 ms 无反应，用 160 ms 立刻挥剑。**定版用 120 ms 最小按住**。
2. **绝不能写 `kCGEventSourceUserData`**。给它赋任何非零值（哪怕是用来做"防自激标记"），
   系统会把事件**当无效事件丢弃**。这是本次最隐蔽的一个坑。
3. **不要在事件拦截回调里 `usleep`**。回调阻塞期间自己 post 的事件会被挤到回调返回后
   一起送达，游戏只看到 1 ms 的按下，等于没按。正确做法：回调里只置标志位，
   在 `CFRunLoopTimer`（10 ms）里真正发送。
4. **必须区分真人输入与自家合成事件**。自己 post 的事件会再次流过自己的 event tap，
   如果不放行，`Shift→空格` 会被 `空格→K` 二次改写，锁定就变成了跳跃。
   判据：`CGEventGetIntegerValueField(ev, kCGEventSourceUnixProcessID) == getpid()`。
5. **视角判定不能用单次事件 delta**。慢速移动时每次 `delta` 只有 1，
   永远达不到死区阈值（6），表现是"视角完全不跟手"。
   正确做法：**累积位移**，超过阈值才转，停手 60 ms 后按 0.6 的比例衰减，
   衰减到阈值以下方向键自然松开。
6. **前台判断必须缓存**。鼠标每秒产生上百条移动事件，
   每次都 `CGWindowListCopyWindowInfo` 全量遍历窗口列表会吃满 CPU 并引入输入延迟。
   **定版 200 ms 刷新一次**。顺带把窗口矩形一起取出来，供捕获时钉光标用。

> 补充坑（鼠标捕获专用）：
> **退出路径必须还原 `CGAssociateMouseAndMouseCursorPosition(1)`**。
> `atexit` 不覆盖 `SIGTERM`，被 `pkill` 杀掉时会漏——必须挂 `signal(SIGINT/SIGTERM/SIGHUP)`。
> 另外测试工具若把事件位置写成 `(0,0)`，等于直接把光标瞬移到原点，会误判成"捕获失效"；
> 模拟相对移动要**保持位置不变、只写 delta**。

### 11.1 结论速览

| 尝试 | 结果 | 结论 |
|---|---|---|
| `DXMT=1`（32 位直连 Metal） | **Kegworks 直接退出**，连 Wine 都没进 | ❌ 不可用，已回滚 |

| `ShadowQuality` / `EffectQuality` / `FilterQuality` / `MotionBlurQuality` / `FrameRateMode` | 游戏退出后**完全不写入** config.ini | ❌ 是引擎内部参数，不是配置键 |

### 11.2 真实瓶颈：重场景是 CPU + GPU 双卡

用 Metal HUD + OCR 在**明亮教堂实时过场**（不是预渲染视频）实测：

| 指标 | 数值 |
|---|---|
| FPS | **19~25** |
| Pre（每帧总毫秒） | **40~52 ms** |
| GPU | **24~28 ms** |
| 差值（CPU 侧） | **约 15~25 ms** |

结论修正：

- 这个场景 **GPU 24~28 ms、CPU 15~25 ms**，两边都不轻松；
- 不是单纯「阴影固定开销」，也不是单纯 Rosetta；
- 降分辨率只能压 GPU 那一半，CPU 那一半（wined3d 绘制调用翻译 + Rosetta）压不动；
- 所以 `1024x576` 仍是甜点，再降收益很小。

## 第 12 节 · 启动器 App（一个 app 管所有设置）

### 12.1 位置与用法

`/Volumes/SSD/Game/DMC4/鬼泣4 启动器.app`

> 被钉在游戏窗口正中心（如 `547,335`）= 捕获生效。
>
> 重映射器已编译进启动器本体（同一进程、同一签名），不再是独立子进程。
> 所以只需要给**启动器 app** 授权，不用管 `dmc4_input_v4`。
>
> 实测：辅助功能一项就够，**不需要**「输入监控」。

### 12.4 重建

```sh
bash "/Volumes/SSD/Game/游戏构建/鬼泣4/_build/build_launcher.sh"
```

> ⚠️ ad-hoc 签名每次重建都会变 cdhash，**已授予的辅助功能权限会失效**。
> 要改面板就先改完、重建完，最后再授权；别反复重建。

### 12.5 和 .command 的关系

`▶ 启动鬼泣4（维吉尔·但丁）.command` 等保留，作为**命令行 / 调试入口**。
注意：双击 `.command` 是由 Terminal 执行的，而 **Terminal 默认不在辅助功能列表里**，
所以双击不一定能接管鼠标；日常请用启动器 app。

### 12.6 光标与视角行为（2026-10-29 新增）

| 场景 | 光标 | 视角 / 输入 |
|---|---|---|
| 游戏内 | **隐藏**，锁定在游戏框内（物理位移与光标解耦） | 鼠标移动转视角；**上移 = 视角上移**（已修正原来的反向） |
| 按 ESC 进暂停菜单 | **显示**，可在游戏框内移动（越界自动拉回） | 不转视角；键鼠全部放行给游戏 |
| 再按 ESC 回游戏 | 重新隐藏，光标回窗口中心 | 恢复转视角 |
| 切到别的窗口 / 长按 Cmd | 显示并释放 | 不转视角 |

> 退出暂停菜单也可以选「EXIT PAUSE MENU」；之后按 WASD 或点鼠标会自动重新捕获。
>
> 实现：`dmc4_input_v4.c` 里 `capture_on/off` 调 `CGDisplayHideCursor/ShowCursor`，
> `menu_mode` 由 ESC 双向切换，`tick_cb` 在菜单模式下把光标钳制在窗口内。
