## 0. 一句话结论

霍格沃茨之遗的数值数据存在游戏的 **SQLite 数据库**里（单库 579 张表）。做数值 mod 的本质是：
**解出 sqlite → 改表里的值 → 合并 → 重新打包成 pak 三件套 → 丢进 `~mods`。**

本次共迭代 **3 轮**才定型，最终产出 `zzz_EasyTimeMerged_P.pak`（8.4M）并已装入游戏生效。

## 2. 方法（已验证可行）

1. **取基准库**：从游戏 pak 解出 `Phoenix` 的 sqlite 数据表，得到 `EasyTimeBase.sqlite`（579 张表，含 `Achievement*`、`Item*`、`Spell*` 等）。
2. **一次只改一件事**：每个改动单独存一个 sqlite，文件名直接写清改了什么（如 `HalfCooldown.sqlite`、`IncendioRange.sqlite`），方便回滚和自由组合。
3. **同一张表被多个改动命中时，先合并**：生成 `MERGED.sqlite`（半冷却版）/ `MERGED_ZERO.sqlite`（零冷却版），再打成包。不合并就打包，后打的会覆盖先打的。
4. **打包成三件套**：`xxx_P.pak` + `xxx_P.ucas` + `xxx_P.utoc`。
5. **三个文件一起拷进 `~mods`**，文件名前缀控制加载顺序（`z` → `zz` → `zzz` 依次覆盖）。

## 5. 踩坑清单（下次直接照这个避）

1. **文件名绝对不要带空格。** 第二轮 10 个文件全带空格，每个都要转义，脚本一改就错，白干一轮。
2. **三件套缺一不可。** `.pak` / `.ucas` / `.utoc` 少任何一个游戏都不认。"mod 装了没效果"九成是只拷了 `.pak`。
3. **加载顺序靠文件名前缀。** `z` < `zz` < `zzz`，要覆盖别人的 mod 就用 `zzz_` 开头。
4. **`_P` 后缀 = patch pak。** 同类资源冲突时优先于原版，命名时保留这个后缀。
5. **数值 mod 会互相覆盖。** 冷却、范围、上限改的是同一批表，同时装多个只有最后一个生效 → **必须先合并成 MERGED 再打包**。这就是 `MERGED.sqlite` / `MERGED_ZERO.sqlite` 存在的原因。
6. **改之前先备份。** 已装 mod 全量备份在 `~/游戏台/霍格沃茨之遗/mods备份/20261030/`（3 个三件套 + 11 个单文件）。
7. **`~mods` 在 Wine 前缀里，路径极深。** 别按原生 Mac 游戏的思路找，用 `find -name "~mods"`。

## 7. 复现步骤（要从头再改一次数值时）

```bash
# 1. 定位 mod 目录
MODS="/Volumes/SSD/Game/HogwartsLegacy/Hogwarts Legacy.app/Contents/SharedSupport/prefix/drive_c/Hogwarts Legacy Complete/Phoenix/Content/Paks/~mods"

# 2. 先备份现有 mod（重要）
mkdir -p "$HOME/游戏台/霍格沃茨之遗/mods备份/$(date +%Y%m%d)"
cp -R "$MODS"/* "$HOME/游戏台/霍格沃茨之遗/mods备份/$(date +%Y%m%d)/"

# 3. 从游戏本体的 pak 里解出基准 sqlite（579 张表）
#    工具链与解包命令见 /Volumes/SSD/Game/HogwartsLegacy/重建实操指引.md

# 4. 每个改动单独另存一个 sqlite，文件名写清改什么，不要带空格

# 5. 所有改动合并成一个 MERGED.sqlite（同一张表只能保留最后一次修改）

# 6. 打包成三件套，前缀用 zzz_ 保证最后加载
#    产出：zzz_XXX_P.pak / .ucas / .utoc

# 7. 三个文件一起拷进 ~mods，启动游戏验证
```

**验证顺序建议**：先只装新 mod 一个，确认生效；再逐个叠加，出问题容易定位是哪一个冲突。

## 8. 归档结论

- 数值 mod 的**方法已经跑通**，核心是 SQLite 改表 + MERGED 合并 + pak 三件套，不依赖专门的 mod 编辑器。
- 本次最大的时间浪费在**文件命名（空格）**和**多 mod 表覆盖**这两件事上，第 5 节已固化。
- 外观类 mod（发型、脸型）**成功率明显低于数值 mod**：4 个尝试里只有 1 个（`zPrettyFaceCustom02`）真正装上。推测是发型/脸型涉及骨骼与材质，版本兼容要求更严——但**没有日志佐证，属推断**。
- 中间文件已全部清除（466M），现有产物足以支撑"直接玩"，但**不足以支撑"改一个数值就重打包"**——后者需按第 7 节从游戏本体重新解包。
